## Issues Encountered

**Task 2 build/test not runnable in the worktree within session/tool constraints.** The worktree has no `build/OSX/Debug` tree. A real regression build requires one of:

1. Reconfiguring the user's 45 GB main build tree (`.../SuperGenius/build/OSX/Debug`) to point `-S` at the worktree source. This would change the main build's `CMAKE_HOME_DIRECTORY`, and because the freshly-checked-out worktree files carry new mtimes, ninja would treat every translation unit as stale and trigger a multi-hour full recompile — and it would leave the user's active build tree misconfigured.
2. A fresh configure inside the worktree. The shared thirdparty artifacts live at a sibling path (`.../GeniusNetwork/thirdparty/build/OSX/Debug`), not inside the repo; the build system's default `THIRDPARTY_DIR` resolves to `SuperGenius/.claude/worktrees/thirdparty` (nonexistent), so a clean configure would attempt a multi-GB thirdparty download and then a multi-hour full compile of the core libraries.

**What was done instead:** Compile-only verification of `src/account/GeniusNode.cpp` using the exact clang++ command, defines, include paths, and warning flags extracted from the main build's `compile_commands.json`, with only the source path pointed at the worktree file and `-fsyntax-only` substituted for `-o`. Result: exit 0, no diagnostics. The change is a pure block move with no new symbols, includes, or signatures, so link-compatibility is unaffected.

**Recommendation:** Run the regression binaries in the user's main checkout (`build/OSX/Debug`) after applying this commit there: `cmake --build build/OSX/Debug --target genius_node genius_node_test node_shutdown_race_test full_node_test`, then run `build/OSX/Debug/test_bin/node_shutdown_race_test` and `build/OSX/Debug/test_bin/full_node_test`.
