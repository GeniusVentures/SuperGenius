<threat_model>
## Trust Boundaries

| Boundary | Risk |
|---|---|
| Certificate ingress sources → finality | Divergent adapters can apply or clean in different orders |
| Replicated certificate → local handler | Crash/failure can duplicate effects or lose pending work |
| Local preference → certificate acceptance | A validator could reject the network winner and retain unsafe state |

## STRIDE Threat Register

| Threat ID | Severity | Category | Mitigation |
|---|---|---|---|
| T-10-05-01 | High | Tampering / Elevation of Privilege | `FinalizeSlot` condition-waits for an earlier exact `SigningPublishing` or `PublishingReplay` generation, then installs one shared-mutex `Finalizing` generation before persistence; finalization-first blocks every later vote publication or replay |
| T-10-05-02 | High | Repudiation | Authoritative certificate persists before marker/handler; Complete persists before cleanup |
| T-10-05-03 | High | Denial of Service / Tampering | Missing/failing handlers retain exact Pending work; restart retries an idempotent winner |
| T-10-05-04 | High | Spoofing | Local best/vote is never a certificate acceptance condition; normalized authoritative winner identity binds the marker |
</threat_model>
