  <action>
Implement one `RecordCertificateConflict(authoritative, incoming, source, now)` used by FinalizeSlot for local/pubsub/recovery and directly by `FilterCertificateDelta` before it returns Reject. In the CRDT pre-merge path, structurally and cryptographically normalize the incoming certificate and authoritative stored certificate before classifying a safety conflict; malformed, noncanonical, bad-signature, or dependency-stalled inputs remain ordinary rejection/retry and create no safety evidence.

Compute SHA-256 over each canonical deterministic certificate byte string, sort the two digests for the record key, and persist evidence plus SlotSafetyRecord in one local RocksDB batch. Preserve directional original/incoming proposal and digest fields inside the record, first source/sources-seen, first/last system timestamps, and observation count. Repeated or reversed pair delivery uses the same key and changes only count, last_seen, and source summary; never store either full certificate payload.

Restore SafetyViolation on startup and check it at proposal admission, candidate deadline/signing recheck, peer vote aggregation/certificate creation, and local certificate publication. It is per-slot: unrelated slots continue. It must not block `FinalizeSlot(Recovery)` from completing the already-authoritative winner's Pending marker. Never overwrite authoritative slot/index, invoke the second handler, or normal-publish/rebroadcast a conflicting certificate.

Add an atomic critical metric (document whether it counts unique pairs; use unique pair count) and a `critical` log containing evidence key, slot, both proposal IDs/digests, source summary, and observation count. Add friend-only readers/observers. Test local, pubsub, CRDT pre-merge, and recovery conflicts; invalid conflict-shaped input; repeat/reverse dedup; evidence schema omitting certificate bytes; zero second handler/publish; per-slot stop with unrelated-slot progress; restart restoration; and original-winner Pending application completion after the safety stop.

<threat_model>
## Trust Boundaries

| Boundary | Risk |
|---|---|
| Replicated delta → pre-merge rejection | A conflict disappears before callback/evidence if not handled in the filter |
| Untrusted certificate → safety stop | Invalid traffic could falsely halt consensus participation |
| Safety stop → original application | Overbroad blocking could prevent recovery of the legitimate winner |

## STRIDE Threat Register

| Threat ID | Severity | Category | Mitigation |
|---|---|---|---|
| T-10-06-01 | High | Repudiation | Record at every ingress including CRDT pre-merge with stable digest-pair evidence |
| T-10-06-02 | High | Denial of Service | Full structural/cryptographic validation precedes conflict evidence and safety stop |
| T-10-06-03 | High | Tampering | Atomic evidence+safety batch; authoritative certificate/index are never overwritten |
| T-10-06-04 | High | Elevation of Privilege | Per-slot gates block new participation but explicitly permit only original-winner recovery |
| T-10-06-05 | Medium | Information Disclosure | Evidence stores digests and identities, never duplicate full certificate payloads |
</threat_model>
