  <action>
Create a separate local-state protobuf with explicit schema version and strict records: `DurableVoteRecord` (Active/Retired, slot, proposal, validator, exact signed vote bytes, exact outbound `ConsensusMessage` bytes, signed proposal/registry validation context, generation, created time, acceptance horizon, publication metadata), `CertificateProcessingRecord` (Pending/Processing/Complete plus slot, canonical certificate digest, proposal and winner identity, lease/attempt metadata), `CertificateConflictRecord` (sorted digest pair, both proposal IDs, sources bitset, first/last seen, count, no certificate payload), and durable `SlotSafetyRecord`.

Implement `ConsensusStateStore` over a `storage::rocksdb::RocksDB` obtained externally. Use `/consensus/local/v2/vote/&lt;validator-hash&gt;/&lt;slot&gt;`, `/process/&lt;slot&gt;`, `/conflict/&lt;slot&gt;/&lt;low&gt;:&lt;high&gt;`, and `/safety/&lt;slot&gt;`. Return `outcome::result` typed classifications where only exact `DatabaseError::NOT_FOUND` is absence. Strict scans must fail on query/read errors, malformed keys, truncated/unknown records, unknown enum states, noncanonical IDs/digests, key/value mismatch, contradictory active generations, invalid process/safety relationships, and envelope bytes that do not contain exactly the stored signed vote bytes.

Serialize mutations under the store mutex. Provide exact-idempotent active-vote put, publication metadata update without changing signed/envelope bytes, durable retirement, pending/processing/complete marker replacement, and one atomic conflict-evidence-plus-safety batch. Reject mismatched occupied identities. Never call `GlobalDB::Put`, register a CRDT listener, or place local records under `/cert/`.

Extend the Wave 0 journal tests with byte-preservation, direct namespace inspection, exact duplicate, mismatched duplicate, retirement commit, conflict pair ordering/dedup, and a table of malformed key/value/version/state/query-error cases. Each corruption case must return an error rather than an empty scan.

<threat_model>
## Trust Boundaries

| Boundary | Risk |
|---|---|
| Durable bytes → restored validator state | Corruption or identity substitution could unlock a second signature |
| Local records → CRDT boundary | Replication could expose validator-private votes or local diagnostics |

## STRIDE Threat Register

| Threat ID | Severity | Category | Mitigation |
|---|---|---|---|
| T-10-02-01 | High | Tampering / Spoofing | Strict version, key/value, validator, slot, proposal, vote/envelope, and state cross-checks fail closed |
| T-10-02-02 | High | Information Disclosure | Direct RocksDB-only namespaces; tests assert no CRDT logical records are emitted |
| T-10-02-03 | High | Elevation of Privilege | Atomic retirement transition prevents a new generation becoming eligible before the old lock is durably unusable |
| T-10-02-04 | Medium | Repudiation | Digest-pair evidence preserves stable identities and observation metadata without duplicate payloads |
</threat_model>
