<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ephemeral genesis signer -> TrustedPeerRegistry | One-time, threshold=1 signer set consisting solely of `bootstrapper_address_`; must never regain signing power after genesis |
| CRDT remote peer -> local SecureCrdt filter | Untrusted remote-originated CRDT deltas at `trusted-peer-registry` and `trusted-peer-registry/sig/<addr>` keys |
| Membership-change proposer -> current signer set | A new membership-change proposal must be evaluated against the CURRENT `cached_peers_`, never a stale snapshot |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Spoofing | `SeedGenesis` | mitigate | Genesis signature verified via `SecureCrdt::AddSignature` against `bootstrapper_address_` only, threshold=1; the ephemeral private key is generated/used/discarded entirely outside the node runtime (test-tooling only, Plan 02), never persisted — this component never has access to sign as the bootstrapper a second time |
| T-10-02 | Tampering | `TrustedPeerListPayload::Verify` | mitigate | Structural validation only (non-empty, no dup addresses, 128-hex-char format) runs before any `Apply()`/cache mutation; malformed bytes rejected by `DeserializeFromBytes` returning false, never thrown |
| T-10-03 | Repudiation / Elevation | `ResolveSignerSet` (signer-set-source cache, D-05) | mitigate | Cache (`cached_peers_`) is updated ONLY inside `TryConfirm`, strictly after `SecureCrdt::ReadIfQuorum` independently confirms quorum over the CURRENT signer set — never speculatively, never from an unconfirmed proposal; the callback never calls back into `ReadIfQuorum` (Pitfall 2), eliminating reentrant/stale-check risk |
| T-10-04 | Tampering (quorum bypass) | `EvaluateQuorum` delegation | accept (mitigated upstream) | Dedup-before-verify and duplicate/invalid signer padding rejection is entirely `multisig::EvaluateQuorum`'s responsibility (Phase 8, shipped) — `TrustedPeerRegistry` never re-implements or bypasses this; TPR-03 grep gate enforces no parallel crypto logic exists here |
| T-10-05 | Information Disclosure | Ephemeral genesis private key | mitigate | Never constructed via `GeniusAccount` (which persists keys to disk); Plan 02's ceremony helper uses `ethereum::EthereumKeyGenerator`'s in-memory-only constructor exclusively, confined to test/tooling code, never the node runtime path |
| T-10-06 | Denial of Service | Sub-quorum membership-change spam | accept | `ProposeMembershipChange`/`SignMembershipChange` are thin wrappers with no new attack surface beyond what `SecureCrdt::ProposeValue`/`AddSignature` (Phase 9, already threat-modeled) already bound; repeated sub-quorum proposals simply never confirm, no new state is applied |

</threat_model>
