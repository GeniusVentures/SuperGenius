<objective>
## This Plan (03-02)

Delivers the tracking entry cleanup mechanism (CLEAN-01): when a proposal times out without reaching consensus, the temporary VERIFYING entry in `tx_processed_m` (created during Phase 1 TRACK-01) is transitioned to FAILED — preventing memory leaks from orphaned tracking entries over sustained multi-hour operation.

The mechanism follows the established callback registration pattern (`SubjectHandler` / `CertificateSubjectHandler`) and bridges two subsystems:
- **ConsensusManager** owns the proposal lifecycle and fires cleanup callbacks on timeout
- **TransactionManager** owns `tx_processed_m` and transitions expired VERIFYING entries to FAILED

Purpose: Close the memory leak from Phase 1's temporary tracking entries — every VERIFYING entry has a terminal path (CONFIRMED via certificate, or FAILED via cleanup callback).
Output: ConsensusManager with ProposalCleanupHandler infrastructure + TransactionManager cleanup handler + Blockchain delegation + tests.
</objective>
