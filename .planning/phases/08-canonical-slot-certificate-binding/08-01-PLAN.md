Output: Dispatch-level Mint slot regression coverage, a narrow private certificate-binding guard, and CRDT-backed no-side-effect rejection coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CRDT / PubSub payload → ConsensusManager | Untrusted certificate bytes and datastore key enter filter, callback, and handler paths. |
| Certificate embedded proposal → slot bookkeeping | A claimed certificate asks consensus to identify a winner and remove all contenders sharing its slot. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `ValidateCertificate`, `FilterCertificate`, `CertificateReceived`, `HandleCertificate` | mitigate | Every ingress recomputes exact embedded proposal identity and canonical slot; only key-aware CRDT paths compare supplied current legacy subject-hash compatibility evidence. Task 2 proves valid keyless acceptance, tampered proposal/payload rejection, and legacy-key mismatch rejection with `ctest --test-dir build -R consensus_pending_lifecycle_test --output-on-failure`. |
| T-08-02 | Denial of service | `ClearProposalSlot` and certificate finality callbacks | mitigate | Make binding rejection return before `CreateProposalState`, `ClearProposalSlot`, registry finalization, handler dispatch, journal completion, dependency wakeup, and certificate submit/write. Task 2 seeds contender and certificate state and proves mismatches cannot replace it or trigger finality/mint-capable effects. |
| T-08-SC | Tampering | Package/dependency supply chain | accept | No package-manager install or new dependency is permitted in this phase; existing C++17, protobuf, CRDT, and GoogleTest facilities are used. |
</threat_model>
