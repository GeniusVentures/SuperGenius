Open questions resolved (from 06-RESEARCH.md):

**A3 (Role::FULL promotion automatic or operator-gated?):** ALGORITHMIC in v1. The promotion rule fires inside ApplyVoteEffects based on weight + penalty thresholds. No operator UI exists and adding one is out of scope. The threshold is configurable in WeightConfig so operators tune it via config, not per-node action. Per A3 recommendation.

**Promotion cap interaction:** A REGULAR validator's weight is capped at `regular_max_weight_` (default 100). The default `full_promotion_weight_=500` is ABOVE this cap, so under default config a REGULAR validator can NEVER reach promotion. This is intentional: promotion requires an operator to raise `regular_max_weight_` (or lower `full_promotion_weight_`) in config, making promotion an opt-in operator decision expressed through config rather than a runtime action. This satisfies the "operator-gated" spirit without requiring a UI. Document this clearly in the config field docstring.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vote history → role promotion | Accumulated correct votes (weight) and absence of penalties drive promotion. An attacker would need to sustain correct voting over time to gain FULL/DIRECT_API status — raising the cost of sybil infiltration of the DIRECT_API cohort. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-12 | Elevation of privilege | Malicious validator gaming promotion to infiltrate DIRECT_API | mitigate | Promotion requires sustained correct voting (weight accumulation) AND clean penalty record. A malicious node must behave correctly long enough to accumulate full_promotion_weight_ before it can defect — by which point its history is on-chain. The penalty gate (penalty_score < threshold) means any defection attempt that gets penalized resets the path. |
| T-06-13 | Tampering | Promotion threshold misconfiguration | accept | Threshold is operator-configured. Default (500 > regular_max_weight_ 100) makes promotion opt-in, preventing accidental mass-promotion. Documented in field docstring. |
| T-06-14 | Repudiation | Non-deterministic promotion across peers | mitigate | Promotion is a pure function of ApplyVoteEffects inputs (entries + registered_votes), which are derived from the same certificate/registry CRDT state on all peers. Deterministic by construction. |
