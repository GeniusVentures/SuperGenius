# Phase 05.2 Plan 01: Bridge V2 Event Registry + X-only Key Decompression Summary

Registered the new `BridgeOutInitiated` event in the evmrelay `EventRegistry` and implemented `DecompressXOnlyPubkey()` using libsecp256k1 to convert a 32-byte X-only compressed public key (plus an explicit Y-parity bool) into the 128-char hex destination that `GetAddress()` returns, with 5 unit tests covering even-Y, odd-Y, invalid-X, not-on-curve, and roundtrip byte-ordering cases.

## What Was Built

### Task 1 — Register BridgeOutInitiated in EventRegistry (commit f8d44b6)
Added a new `r.register_event("BridgeOutInitiated(address,uint256,uint256,uint256,uint256,bytes32,bool)", {...})` call inside the `event_registry()` singleton lambda in `evmrelay/include/eth/eth_watch_cli.hpp`, immediately after the retained `BridgeSourceBurned` registration:
- Params 0-4 identical to v1 (`kAddress` indexed sender, four `kUint`).
- Param 5 `{kBytes32, false, "sgnsDestination"}` — fixed 32-byte X-only key (maps to `codec::Hash256` in the AbiValue variant).
- Param 6 `{kBool, false, "destinationYOdd"}` — explicit Y parity (false=even/0x02, true=odd/0x03).

The old `BridgeSourceBurned` registration is retained unchanged for backward-compatible catch-up scanning of v1 burns already on-chain (D-05).

### Task 2 — Implement DecompressXOnlyPubkey (commit 032fefb)
Added a free function in namespace `eth`:
```cpp
[[nodiscard]] std::optional<std::string> DecompressXOnlyPubkey(
    const std::array<uint8_t, 32>& contract_x_bytes,
    bool                           destination_y_odd) noexcept;
```
- Declaration in `evmrelay/include/eth/secp256k1_utility.hpp` (Doxygen header).
- Implementation in `evmrelay/src/eth/secp256k1_utility.cpp`.
- Flow: reject all-zero X (point at infinity) → select prefix from `destination_y_odd` (0x02 even / 0x03 odd) → reverse contract bytes to big-endian → build 33-byte compressed key → `secp256k1_ec_pubkey_parse` (returns 0 = not on curve → nullopt) → serialize uncompressed → extract Y (indices 33..64), reverse to contract order → concatenate hex(X) + hex(Y) = 128 chars.
- Thread-safe: creates/destroys a `secp256k1_context` per call (`SECP256K1_CONTEXT_NONE`), matching the existing `secp256k1_utility.cpp` pattern.
- Constants: `kXOnlyKeyBytes=32`, `kCompressedKeyLen=33`, `kEvenYParityPrefix=0x02`, `kOddYParityPrefix=0x03`.

### Task 3 — Decompression unit tests (commit 5c755c7)
Added 5 tests to `evmrelay/test/eth/secp256k1_utility_test.cpp`:
- `DecompressEvenYKnownVector` — known even-Y key → 128-char result matches expected X+Y.
- `DecompressOddYKnownVector` — known odd-Y key → 128-char result; differs from even-Y for the same X.
- `DecompressInvalidX` — all-zero X → nullopt (both parity flags).
- `DecompressInvalidXNotOnCurve` — 0xFF…FF X → nullopt (both parity flags).
- `DecompressRoundTrip` — derive key from private key seed 0x07, decompress with correct parity, verify destination equals expected X+Y; verifies the X half equals the input.

Test vectors are derived deterministically from libsecp256k1 itself (via `secp256k1_ec_pubkey_create` + serialize) rather than hand-computed, which keeps them reproducible and ties ground truth to the same audited library. Full suite: 11/11 pass (6 pre-existing + 5 new).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Strip `0x` prefix from hex_bytes output in DecompressXOnlyPubkey**
- **Found during:** Task 3 (tests initially produced 132 chars instead of 128)
- **Issue:** The plan's `<action>` step 9 and RESEARCH.md byte-flow both specified the destination as `hex_bytes(contract_X, 32) + hex_bytes(contract_Y, 32)`, expecting 128 chars. However, `rlp::base::parse::hex_bytes(const uint8_t*, size_t)` prepends a literal `"0x"` to its output (verified in `evmrelay/src/base/parse_utility.cpp:123-133`), producing 2 + 64 = 66 chars per half → 132 chars total. `GetAddress()` returns a plain 128-char hex string with no prefix (`PUBLIC_KEY_HEX_LENGTH = 128` in `src/account/GeniusAccount.cpp:33`), so the decompressed destination would not match the account address.
- **Fix:** Strip the leading 2 chars (`"0x"`, length `kHexCharsPerByte`) from each `hex_bytes` half before concatenating, yielding a plain 128-char hex string. Applied symmetrically to the test's `expected_destination` helper.
- **Files modified:** `evmrelay/src/eth/secp256k1_utility.cpp`, `evmrelay/test/eth/secp256k1_utility_test.cpp`
- **Commit:** 5c755c7

**2. [Rule 3 - Blocking] Plan verify target name `evmrelay_eth` does not exist**
- **Found during:** Task 1 verification
- **Issue:** The plan's `<verify><automated>` block specified `ninja evmrelay_eth`. The actual ninja target for the eth OBJECT library is `eth` (umbrella target `evmrelay` also exists). `evmrelay_eth` is not a real target.
- **Fix:** Used `ninja eth` (and `ninja secp256k1_utility_test`) for verification. No code change required; documented here for the verifier and downstream plans.
- **Commit:** N/A (verification-command correction only)
