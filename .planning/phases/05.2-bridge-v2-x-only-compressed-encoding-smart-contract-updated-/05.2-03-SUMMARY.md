# Phase 05.2 Plan 03: Dual-Topic0 Catch-Up Scan with V2 X-only Decompression Summary

Updated `GeniusNode::PerformStartupCatchupScan()` to issue two `eth_getLogs` calls per chain (one for the v1 `BridgeSourceBurned` topic0, one for the v2 `BridgeOutInitiated` topic0), merge the results through a shared tx_hash deduplication set, and for v2 logs decode the ABI `log.data` to extract the 32-byte X-only key plus the explicit Y-parity bool, decompress via `eth::DecompressXOnlyPubkey()`, and pass the full 128-char destination to `MintFunds()` (D-11, D-12, D-13). The v1 catch-up path is preserved unchanged.

## What Was Built

### Task 1 — V2 topic0 query + merged dedup (commit 54e7846e)

In `src/account/GeniusNode.cpp`:
- Added the v2 event signature `BridgeOutInitiated(address,uint256,uint256,uint256,uint256,bytes32,bool)` and computed its topic0 hash via `eth::abi::event_signature_hash()` alongside the existing v1 topic0.
- Refactored the per-chain log-processing loop into a `process_logs` helper lambda taking a `std::vector<eth::rpc::RpcLog>` and an `is_v2` flag, with a single `std::set<std::string> seen_tx_hashes` shared across both queries (D-12).
- Added a second `eth_getLogs` call per chain (same contract address + block range, v2 topic0, request id `kV2LogsRequestId = 2`) — required because `EventFilter` topics are single-value-per-position with no OR-array support.
- Made error handling best-effort per query: a failed v1 RPC call now logs a warning and falls through to the v2 query instead of skipping the whole chain.
- Added includes `#include <eth/eth_watch_cli.hpp>` and `#include <eth/secp256k1_utility.hpp>` (consumed by Task 2) plus `#include <set>`.
- V2 destination decompression was a placeholder (empty) pending Task 2.

### Task 2 — V2 X-only decompression before MintFunds (commit d0ac829f)

Replaced the Task 1 placeholder inside the `is_v2` branch of `process_logs`:
- Looks up `BridgeOutInitiated` params from `eth::cli::event_registry().params_for()` and filters to the 6 non-indexed params (sender is indexed → in topics[1]; id/amount/srcChainID/destChainID/sgnsDestination/destinationYOdd are in `log.data`).
- Calls `eth::abi::decode_log_data(rpc_log.log.data, non_indexed_params)` and validates the result has at least 6 values.
- Extracts the bytes32 `sgnsDestination` (non-indexed index 4) via `std::get<eth::codec::Hash256>` and the `destinationYOdd` parity bool (index 5) via `std::get<bool>`, with `std::holds_alternative` type checks before each `std::get`.
- Calls `eth::DecompressXOnlyPubkey(x_bytes, destination_y_odd)` with the explicit parity bit the v2 event carries.
- On decode failure, type mismatch, or decompression failure: logs a warning, increments `total_skipped`, and `continue`s (T-05.2-09 mitigation — no silent skip).
- Passes the resulting 128-char destination to `MintFunds`; the v1 path retains its existing empty-destination call unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking interface mismatch] Adapted to Plan 01's actual DecompressXOnlyPubkey signature**
- **Found during:** Task 2 (read the main-repo working tree where Plan 01 was being implemented)
- **Issue:** This plan's `<interfaces>` and Task 2 `<action>` specified `DecompressXOnlyPubkey(const std::array<uint8_t, 32>&)` returning a parity-trial result, and the v2 event `BridgeOutInitiated(...,bytes32)` with 6 params. The Plan 01 agent's actual implementation diverged: it added a 7th `bool destinationYOdd` param to the event and a matching second argument to `DecompressXOnlyPubkey`, removing the Y-parity ambiguity (a cleaner, deterministic design).
- **Fix:** Followed the real Plan 01 interface. Decoded 6 non-indexed params from v2 log data (not 5), extracted both the bytes32 X key (index 4) and the bool parity (index 5), and called `DecompressXOnlyPubkey(x_bytes, destination_y_odd)` with two arguments.
- **Files modified:** `src/account/GeniusNode.cpp`
- **Commit:** d0ac829f

**2. [Rule 2 - Input validation] Added variant type guards before std::get on untrusted RPC data**
- **Found during:** Task 2
- **Issue:** The plan's code sketch used `std::get<eth::codec::Hash256>` directly on decoded ABI values. RPC log data crosses the trust boundary (T-05.2-08) and a malformed/garbled log could hold a different variant, throwing `std::bad_variant_access`.
- **Fix:** Added `std::holds_alternative<eth::codec::Hash256>(...)` and `std::holds_alternative<bool>(...)` checks before the `std::get` calls, with skip-and-warn on mismatch.
- **Files modified:** `src/account/GeniusNode.cpp`
- **Commit:** d0ac829f
