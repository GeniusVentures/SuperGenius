<objective>
Build the majority-floor quorum validation helper (D-07, security-critical) shared by both consumers, retrofit the already-shipped `TrustedPeerRegistry::New` to enforce it (breaking API change, callers updated), and build the new `BurnConfigPayload`/`BurnConfig` component on top of `SecureCrdt`/`SecureCrdtRegistry`/`TrustedPeerRegistry` — genesis auto-seed (D-01/D-02/D-03), signer-set-source (D-05), and cache-refresh-via-quorum-re-derivation (Pitfall 2).

Output: `ValidateQuorumThreshold` helper, retrofitted `TrustedPeerRegistry::New`, new `BurnConfigPayload`/`BurnConfig` classes, and passing tests for genesis auto-seed, cache-refresh re-derivation, and both registries' floor-rejection behavior.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local config file → quorum threshold | `quorum_threshold` values for both `TrustedPeerRegistry` and `BurnConfig` originate from locally-editable JSON config, evaluated independently by each node against its own local signer-set-source |
| CRDT peer-originated deltas → SecureCrdt local write gate | `sig/<addr>` and base-key elements arriving from other peers cross into this node's trust boundary via `GlobalDB`'s filter callbacks |
| Node's own signing key → genesis auto-sign | `GeniusAccount::Sign` is invoked automatically (no human approval) exactly once for the BurnConfig genesis default |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | Locally-edited `quorum_threshold` config value | mitigate | `ValidateQuorumThreshold` majority-floor check (`ceil(0.51*signer_set_size)`) enforced at construction time in BOTH `TrustedPeerRegistry::New` and `BurnConfig::New`; construction FAILS (no silent clamp/warning) if violated (D-07) |
| T-11-02 | Elevation of Privilege | `BurnConfig`'s genesis auto-sign path | mitigate | Auto-signing gated to the exact known genesis default value (100) only, checked once at `BurnConfig::New()` construction time, never inside the ongoing `OnCrdtElementChanged` refresh callback — no code path auto-signs a non-genesis proposal (D-03) |
| T-11-03 | Tampering | Cache-refresh callback trusting positional `new_data` | mitigate | `OnCrdtElementChanged` always re-runs `SecureCrdt::ReadIfQuorum(base_key_)` fresh rather than trusting the just-arrived element, since a `sig/<addr>` child can be the element that completes quorum (Pitfall 2) |
| T-11-04 | Repudiation/Tampering | Bespoke signature/quorum logic reimplemented for BurnConfig | mitigate | All propose/sign/quorum operations delegate to already-shipped `SecureCrdt`/`SecureCrdtRegistry`/`multisig::EvaluateQuorum` — no parallel verification logic introduced (TPR-03 precedent extended) |
| T-11-05 | Denial of Service | Malformed/oversized `BurnConfigPayload` bytes from a peer | accept | `SecureCrdt::ProposeValue`'s existing local codec/semantic check (DeserializeFromBytes + Verify) already rejects malformed payloads before Put; `BurnConfigPayload::Verify`'s structural bound check (`<= 10000`) is a cheap, bounded parse — no new DoS surface introduced beyond what Phase 9 already covers |

</threat_model>
