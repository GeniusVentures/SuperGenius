    **D-01, D-02, D-03, D-21** — Refactor BridgeRelayer for multi-chain:

    1. In BridgeRelayer.hpp, add a `ChainContractPair` struct (PascalCase, per CONVENTIONS.md) with `std::string chain_name` and `std::string contract_address`. Place it in namespace sgns, above the BridgeRelayer class. See RESEARCH.md Pattern 2 for exact signature.

    2. Change `Start()` signature from `void Start(const std::string &chain_name, const std::string &contract_address)` to `void Start(std::vector<ChainContractPair> chains)`.

    3. Replace single `eth::EventWatchId watch_id_{ 0 }` member with per-chain map: `std::unordered_map<std::string, eth::EventWatchId> chain_watches_` keyed by chain_name. Keep the friend class accessor for BridgeRelayerTestAccess — the accessor must also expose chain_watches_ for testing.

    4. Rewrite Start() body: iterate `chains` vector. For each pair, parse contract_address via `rlp::base::parse::hex_array()`. If invalid, log error with chain_name and **continue** (D-21 best-effort: skip failed chain, don't return). Register `BridgeSourceBurned(address,uint256,uint256,uint256,uint256)` watch via `watch_service_->watch_event(addr, event_sig, params, callback)` using the same event signature string as the existing code (line 97). Store watch_id in `chain_watches_[chain_name]`. Log: "BridgeRelayer: watching {} contract={} watch_id={}". After loop, log summary: "BridgeRelayer: started watching {} of {} chains".

    5. Update OnWatchEvent log messages to include `chain_name` — but OnWatchEvent currently receives `eth::WatchEventNotification` which has no chain_name. The callback in Start() captures the chain name via lambda: `[weakptr{weak_from_this()}, chain_name](const eth::MatchedEvent &event, const std::vector<eth::abi::AbiValue> &values) { ... }`. Pass chain_name to OnWatchEvent by adding a `const std::string &chain_name` parameter to the private `OnWatchEvent` method signature. Log "BridgeRelayer: burn detected chain={} tx={} ..." where chain is the captured chain_name (already in the existing log format).

    6. D-02: chains without bridge_contract_address — Start() receives only chains that HAVE the field. The filtering happens at the call site (Plan 05-05, GeniusNode). BridgeRelayer does NOT filter; it registers whatever it's given.

    7. Keep the existing `Stop()` method unchanged. Keep the existing `Create()` factory unchanged.

    8. Follow codebase conventions: PascalCase for ChainContractPair, camelCase for member variables, `const std::string &` for string parameters, outcome::result for fallible operations (not needed here, Start is void).
  </action>
