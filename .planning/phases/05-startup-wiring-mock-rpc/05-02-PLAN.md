    Implement `mock_rpc_transport.cpp` and `mock_rpc_config.hpp` (LoadMockConfig function).

    **MockRpcTransport::call() implementation** (D-07, D-10, D-13):

    `call()` receives a `boost::json::object` request matching `eth::rpc::make_get_transaction_receipt_request()` format. The request object has fields like `"method": "eth_getTransactionReceipt"` and `"params": ["0xtxhash..."]`.

    1. Extract tx_hash from request: access `request.at("params").as_array()[0].as_string()` — the first param is the tx_hash
    2. Increment `call_count_`
    3. Switch on `config_.behavior`:

       - `kSuccess`: Look up `tx_hash` in `config_.responses`. If found, get the next response from the ordered vector using `response_index_[tx_hash]` as index, then increment the index. Return the canned JSON string wrapped in `std::optional<std::string>`. If tx_hash not in responses map, return a valid receipt JSON (a default success receipt with status=1 and matching bridge contract address in logs — construct a minimal valid `eth_getTransactionReceipt` JSON using boost::json::object).

       - `kTimeout`: Return `std::nullopt` (simulates RPC timeout — no response).

       - `kConnectionRefused`: Return `std::nullopt` (simulates connection failure — same as timeout from caller's perspective per RESEARCH.md Pitfall behavior).

       - `kBadJson`: Return a string that is NOT valid JSON: `"{broken"` wrapped in optional. The caller's `parse_transaction_receipt_response()` will fail to parse it.

       - `kWrongStatus`: Return a valid receipt JSON where `result.status` is `"0x0"` (failed transaction status). The validator rejects on `!receipt->receipt.status.value()` at PublicChainInputValidator.cpp:211.

       - `kWrongLogs`: Return a valid receipt JSON with `result.status = "0x1"` but with `result.logs` array containing a log whose `address` does NOT match `config_.url` (use a different address like `0x0000000000000000000000000000000000000000`) and whose `topics[0]` does not match the expected event topic0. The validator rejects on log mismatch at PublicChainInputValidator.cpp:234.

    **LoadMockConfig() implementation** (D-08, D-09):

    Parse `<binary_dir>/mock_rpc_config.json` using `boost::json::parse()`. The JSON structure:
    ```json
    {
      "endpoints": [
        {
          "url": "https://mock-rpc-1.example.com",
          "behavior": "success",
          "responses": {
            "0xabc123...": ["{\"jsonrpc\":\"2.0\",\"id\":1,\"result\":{...}}"],
            "0xdef456...": ["resp1", "resp2"]
          }
        }
      ]
    }
    ```
    For each endpoint object, parse `url` (string), `behavior` (string → MockBehavior enum: map "success"→kSuccess, "timeout"→kTimeout, "connection_refused"→kConnectionRefused, "bad_json"→kBadJson, "wrong_status"→kWrongStatus, "wrong_logs"→kWrongLogs), `responses` (object of tx_hash → array of strings). Populate `MockEndpointConfig` for each. If the file doesn't exist (`std::filesystem::exists()` returns false), return empty vector — no error.

    **Don't implement:**
    - JSON-RPC request validation beyond extracting tx_hash
    - Multi-thread safety (tests are single-threaded)
    - Response format validation (canned responses are opaque JSON strings per D-11)

    Follow Don't Hand-Roll (RESEARCH.md lines 266-273): use `boost::json::parse()` for config, `boost::json::serialize()` for constructing default receipts.
