<objective>
Build the in-process MockRpcTransport class that implements eth::rpc::JsonRpcTransport — a drop-in replacement for RpcHttpTransport per D-07. Supports all 6 failure modes per D-13, stateful response sequences per D-10, per-node JSON config per D-08/D-09, and comprehensive behavioral tests. Addresses REQ-MOCK-01, REQ-MOCK-02, REQ-MOCK-03.

PublicChainInputValidator iterates chains from chains_config.json and creates a transport per endpoint URL. The mock matches endpoint behavior by URL key in mock_rpc_config.json. The mock does NOT independently parse chains_config.json — that responsibility stays with ChainRpcEndpointProvider and InitializeRpcEndpoints().

Purpose: Enable Tier 1 RPC verification testing without live testnet dependencies, compile-time flags, or mocking framework dependencies.

    **MockRpcTransport::call() implementation:**

    `call()` receives a `boost::json::object` request. Extract tx_hash from `request.at("params").as_array()[0].as_string()`. Increment `call_count_`. Switch on `config_.behavior`:

    - `kSuccess`: Look up tx_hash in `config_.responses`. If found, return responses vector at `response_index_[tx_hash]` index (then increment, wrapping via modulo). If tx_hash not in responses, return a default valid receipt JSON with status=1 and empty logs. Wrap in `std::optional<std::string>`.

    - `kTimeout`: Return `std::nullopt`.

    - `kConnectionRefused`: Return `std::nullopt`.

    - `kBadJson`: Return `"{broken"` wrapped in optional. Caller's parse_transaction_receipt_response() fails to parse.

    - `kWrongStatus`: Return valid receipt JSON where `result.status` is `"0x0"`. Validator rejects on `!receipt->receipt.status.value()`.

    - `kWrongLogs`: Return valid receipt JSON with status=1 but logs containing wrong address and mismatched topic0. Use `0x0000000000000000000000000000000000000000` as wrong address and a different topic0.

    **LoadMockConfig() implementation** (D-08, D-09):

    Parse `<binary_dir>/mock_rpc_config.json` with `boost::json::parse()`. JSON structure: `{"endpoints": [{"url": "...", "behavior": "success"|..., "responses": {"0xtxhash...": ["..."]}}]}`. Map behavior strings to MockBehavior enum. Populate MockEndpointConfig per endpoint. File doesn't exist → return empty vector.

    Follow Don't Hand-Roll: use `boost::json::parse()` for config, `boost::json::serialize()` for constructing default receipts.
