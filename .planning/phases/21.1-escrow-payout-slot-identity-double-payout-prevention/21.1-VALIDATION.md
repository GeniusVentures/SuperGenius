This contract describes checks to implement and run during execution. Research did not run the suites. The planner must replace the provisional verification map with actual plan/task IDs and commands before the phase is marked planned.

| Property | Value |

| Full suite command | `ctest --test-dir build/OSX/Release --output-on-failure -j1` |

Use `cmake --build` with the configured generator; do not assume Ninja from a stale file. Rebuild SGTransactionProto and ConsensusProto through CMake; never edit generated protobuf output. CTest selects executable names, while GTest filters select individual cases. The existing consensus_certificate_test.cpp registration is commented out and is not a runnable target unless execution explicitly registers it.

## Sampling Rate

- After every task commit: build affected targets and run its focused codec/slot/validation or fixture filter.
- After every plan wave: run the affected regression targets. Do not substitute an unregistered target or an unrelated passing test.
- Before phase verification: run the focused regression set, real-network escrow battery, relevant Debug/Release cases, format/required tidy checks, and full available suite. Report pre-existing failures and unavailable checks explicitly.
- Target fast feedback latency: 30 seconds after build. Network/restart and full-suite runs are separate from that fast budget; record measured duration rather than assert an unmeasured bound.
- No three consecutive tasks without automated verification. Every missing case/target must be created by an explicit predecessor task or in the same task before its verify command.
