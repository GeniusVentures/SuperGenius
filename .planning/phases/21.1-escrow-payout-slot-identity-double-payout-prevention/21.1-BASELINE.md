## Interface reconciliation

- Use `LoadVerifiedRegistryByCid`; the former `LoadRegistryByCid` API is removed.
  Pin the authorized full-node address before constructing fresh strict-path
  registry/certificate fixtures, retaining that authority across restart.
- A canonical slot's mere existence does not grant grandfathering: the durable
  certificate's serialized content must match the candidate exactly.
- `GetCertificateBySlot` collapses pending validation into `invalid_argument`;
  plans 03/06 must retain retryable missing-evidence handling using the owning
  consensus contract rather than treating that error alone as permanent.
- Fresh value-bearing legacy mint submission is rejected. Live payout fixtures
  need valid V2 funding or explicitly certified historical seeding.
- Mint's exactly-one-output burn binding does not apply to V2 escrow payouts,
  which retain their existing multi-recipient distribution.
- Mint slot identity, virtual embedded `GetSlotID` dispatch, exact certificate
  binding, legacy tag 7 and available V2 tag 10 remain valid assumptions.
