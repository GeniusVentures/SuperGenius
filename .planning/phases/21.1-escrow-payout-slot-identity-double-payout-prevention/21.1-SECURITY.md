## Resolved Implementation Findings

### SG-01 — RESOLVED: malformed release decoding failed open at manager entry points

**Closure:** `7175219e312e4abfdfb9a49ddf7653e68483a3b8`. The shared `DecodeTransactionBytes` helper rejects both absent codecs and null results (`TransactionManager.cpp:2413–2430`). Both raw overloads and all embedded oneof branches call it. Slot reconstruction checks success plus non-null (`TransactionConsensusHandler.cpp:64`); actual nonce admission returns Reject on failed/null decode (`:285`). Source regressions cover malformed V2 and historical marker bytes through string/buffer/embedded manager dispatch, actual slot-key reconstruction and actual nonce admission (`escrow_release_v2_test.cpp:928`, `:990`), with signed compatibility controls (`:953`). The negative fixture first asserts failed dispatch, so the RED fails on the contract without deliberately crashing the test runner. No entry point retains the original successful-null contract.

**Initial finding history at `0c8d251afd79d82f6063e243c4f8f18a7d3a4852` (line references in this history refer to that head):**

**Threat:** T-21.1-02-02. **Files searched:** `src/account/EscrowReleaseTransactionV2.cpp`, `src/account/EscrowReleaseTransaction.cpp`, `src/transaction/TransactionManager.cpp`, `src/transaction/TransactionConsensusHandler.cpp`, `test/src/account/escrow_release_v2_test.cpp`.

The checked V2 decoder returns `nullptr` for malformed type/shape/hash/token/canonical bytes (`EscrowReleaseTransactionV2.cpp:82–119`); the legacy decoder also returns null for rejected input (`EscrowReleaseTransaction.cpp:100–112`). `TransactionManager::DeSerializeTransaction` directly returns that shared pointer as its successful outcome payload (`TransactionManager.cpp:2421`). Both new embedded release branches do the same (`:2488`, `:2495`). Consequently `has_value()` can mean a successful null pointer. The registered peer slot handler tests only `tx.has_value()` before `tx.value()->GetSlotID()` (`TransactionConsensusHandler.cpp:63–66`). An embedded V2 with a valid protobuf envelope and missing/invalid payment shape therefore reaches a null dereference before safe rejection. Other embedded consumers also assume non-null successful results.

**Original required mitigation (now verified):** propagate codec null rejection as a failed manager result for raw and embedded dispatch, and prove malformed release bytes through actual manager/slot/subject entry points cannot dereference null or become admitted. The class-level malformed-codec test at `escrow_release_v2_test.cpp:953` does not cover this integration contract. No fix was made by this auditor.

### SG-02 — RESOLVED: normal hold pruning prevented V2 replay/rebuild and own-effects rollback

**Closure:** `661531ccc9d48eb9d97966e9d9cc35d841bc851d`. `ResolveCertifiedEscrowHold` (`GeniusInputValidator.cpp:148`) validates any available raw producer before lookup; a false raw hold is Invalid, while storage/missing/deferred evidence stays Pending and rejected authority is Invalid. Raw NOT_FOUND uses the new thin exact-hash lookup (`:181–189`). Both owning lookup APIs call the same read-only scan (`Consensus.cpp:5007`, `:5017`), which decodes keys, checks canonical placement, calls `GetCertificateBySlot`/`ValidateCertificate`, compares readback bytes and rejects duplicate matches (`:5054–5068`). No alias, durable index or new finality store is introduced.

The account helper then requires exact embedded escrow type, hash/CheckHash, actual lock output, source/nonce via `CertificateMatchesTransaction`, virtual slot, original embedded encoding and available raw-byte equality (`GeniusInputValidator.cpp:191–218`). V2 application/revert and historical escrow owner recovery all call this helper (`TransactionManager.cpp:3240`, `:3306`, `:2855`). Genuine durable/current own-spender checks still guard payout rebuild and rollback (`:3265`, `:3328`), with consume-before-produce and correct-owner restore unchanged. Source regressions prune the actual hold through the existing guarded lifecycle, reopen storage, reject losing/foreign spenders, replay exact outputs once and restore the original owner/token/amount (`transaction_manager_pending_lifecycle_test.cpp:1068`, `:2089`, `:2102`, `:2128`, `:2232`, `:2288`). Missing/deferred/rejected authority and exact subject/type/source/nonce/encoding negatives are present at `:1124`, `:1183`. This verifies the authored replay/recovery mitigation; it does not alter the historical-finality transfer boundary.

**Initial finding history at `0c8d251afd79d82f6063e243c4f8f18a7d3a4852` (line references in this history refer to that head):**

**Threats:** T-21.1-04-01 and T-21.1-06-02. **Files searched:** `src/account/GeniusInputValidator.cpp`, `src/transaction/TransactionManager.cpp`, `src/transaction/PruneEligibility.cpp`, `test/src/account/transaction_manager_pending_lifecycle_test.cpp`.

`ResolveEscrowReleaseInput` reads only the raw hold transaction value and returns `kNotSynced` when it is absent (`GeniusInputValidator.cpp:143–148`). It does not recover a legitimately pruned hold from the retained exact canonical certificate. The existing pruner treats produced UTXOs generically: a genuine consumed hold output with recorded spender and elapsed spend window can become eligible (`PruneEligibility.cpp:489–581`); no escrow-hold exclusion protects that value. The guarded erase retains canonical certificate authority.

V2 parse requires this resolver before reaching durable own-spender recovery (`TransactionManager.cpp:3250–3262`, `:3275–3287`). Applied V2 revert also resolves first and returns an error when an own spender exists but the hold value has been pruned (`:3316–3325`). Thus retained genuine spender/certificate evidence cannot restore the original owner's effects after an ordinary supported pruning/restart history. The existing restart test prunes only the payment value (`transaction_manager_pending_lifecycle_test.cpp:1900`) while keeping the producer hold value available; it does not verify this boundary.

**Original required mitigation (now verified):** recover the exact hold through existing owning canonical certificate authority when the raw value is legitimately unavailable, preserving exact hash/type/slot/content binding and missing-versus-invalid behavior. Add real prune/restart/replay and guarded own-effects rollback regressions, retaining foreign-spender/loser negatives. This is an implementation recovery gap, not authorization to add a finality store, disable pruning or accept the risk. No fix was made by this auditor.
