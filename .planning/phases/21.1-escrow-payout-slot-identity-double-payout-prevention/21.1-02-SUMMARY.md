## Decisions Made

- Canonical V2 bytes are a decoder invariant: reconstruction must equal input bytes. This prevents accepted uppercase input hashes, unknown discarded fields or other noncanonical forms from silently changing signed content. The slot itself contains only the normalized actual input outpoint; actual-hold/certified-producer validation belongs to plan 03.
- Legacy marker UTXOs have a direct inspection getter but retain the base's disabled generic payment interface. Their historical fields/signature remain available without acquiring V2 funds-moving behavior.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Replaced unsafe hash parsing in the new V2 decoder**
- **Found during:** Task 2 read-only review and malformed-input regression.
- **Issue:** The named analog's `Hash256::fromReadableString` throws for exact-length nonhex data, accepts partial hex pairs and permits a 65-character out-of-bounds write. The initial new-code call inherited this unsafe boundary.
- **Fix:** Used existing checked `Hash256::fromHex`; tested 64 nonhex characters, 65 characters and partial hex pairs. The legacy decoder also uses the checked helper. No out-of-scope global hash parser was modified.
- **Verification:** The exact-length malformed RED test reproduced the exception, then all final cases passed.
- **Commit:** `8080e5754` (legacy use in `00408c032`).

**2. [Rule 2 - Missing critical functionality] Prevented V2 signed-byte normalization**
- **Found during:** Task 2 codec review.
- **Issue:** A parsed uppercase input hash or discarded protobuf fields could otherwise be reconstructed differently while retaining the original DAG signature/hash.
- **Fix:** Reject V2 inputs whose complete reconstructed canonical bytes differ. Added uppercase and unknown-field rejection cases and invalid local-slot-shape assertions.
- **Verification:** All V2 raw/embedded and malformed cases pass.
- **Commit:** `8080e5754`.
