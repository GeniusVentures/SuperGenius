## Accomplishments

- Added ConsensusManager::FindCertificateByNonceSubject and a thin Blockchain forward. The fallback queries existing canonical `/cert/` records through GlobalDB, decodes query keys through KeyToString, validates each matching record through GetCertificateBySlot, checks scanned/readback content equality and rejects ambiguous or contradictory records. It writes no alias, index or finality record and contains no account transaction decoding.
- Refined GetCertificateBySlot using its existing ValidateCertificate authority: absent records retain NOT_FOUND, storage failures propagate, rejected certificates return invalid_argument, and Pending/Stalled authority returns resource_unavailable_try_again. Corrupt signatures, insufficient signed votes, registry binding mismatch, wrong keys and ambiguity reject; a signed missing-registry dependency remains retryable.
- Replaced the two predecessor fallback assumptions with one private TransactionManager resolver. Known tracked/value/registration predecessors use their own virtual slot; missing values recover through the owning nonce lookup with a durable/claimed exact hash where available. The consumer independently checks the embedded CheckHash, expected hash, source, nonce, derived slot, CertificateMatchesTransaction and exact known-versus-embedded bytes. Outgoing recovery without durable expected history requires a unique canonical subject. Ordinary account nonce ordering, reservations and Mint policy were retained.
- Removed the hold resolver's temporary raw-certificate probe. It now consumes the owning classified error directly: definite rejection is Invalid, while missing, storage and deferred authority remain Pending. The full V2 admission fixture retains its missing producer/certificate twins and now rejects corrupt votes.
- Added nine named real-boundary cases across the two existing fixtures. A confirmed V2 value is physically pruned through the existing guarded lifecycle, a fresh manager is constructed, and the next signed ordinary transaction carries and validates the exact V2 previous_hash. Independent binding negatives preserve Pending for genuinely missing certificates.
- Payment cases use certified holds, independently signed V2 competitors, exact canonical winner assertions, durable genuine hold-spender evidence, every peer/developer/burn output and exact recipient balances. Concurrent duplicates, both arrival orders, repeated loser/winner delivery, own-spender rebuild, foreign-spender refusal and repeated never-applied loser reversal preserve one payment. Actual PutUTXO output-store failure occurs after durable consume and leaves VERIFYING/effects_applied=false until retry. Restart releases/reloads the ledger storage while retaining canonical records; UTXO initialization still precedes pending certificate replay.
- Separate historical replay proves legacy markers create no funds, uncertified historical Transfer cannot forge application evidence, exact certified historical Transfer pays once, and V2 pays separately across restart. Existing shared payment helpers required no behavioral changes.
