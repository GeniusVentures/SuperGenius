## Accomplishments

- Added the non-pure transaction-aware validator adapter with an explicit address argument. Other chain validators retain their existing boolean implementation; the Genius override rejects a source mismatch and uses only the typed release's signed parameters.
- `ResolveEscrowReleaseInput` owns signed V2 shape, sole output-zero input, one producer-buffer snapshot, exact hash/CheckHash, actual EscrowTransaction type and lock output, approved canonical certificate lookup and exact CertificateMatchesTransaction binding. Success returns an immutable producer. Uncle text and claimed ownership grant no authority.
- Extracted existing locked UTXO verification before changing behavior. Ordinary verification now requires source ownership. The dedicated release wrapper derives its owner from the actual hold and checks tracked amount/token against that producer under the same shared lock as signature, duplicate, READY/RESERVED state, ownership and checked input/output totals. It exposes no arbitrary-owner or allow-non-owned switch.
- Witnesses resolve the same actual hold, use the release's own parameters, compare the entire canonical input leaf to its actual outpoint/owner/token/amount and retain all existing commitment/Merkle/signature/token-hook/balance checks. The second approved certificate lookup still repeats exact producer binding. Ordinary ownership is strict; certified-parent Transfer signature delegation remains intact.
- Type rules return ValidationResult. Both typed local missing evidence and witnessed PENDING now return existing deduplicated Certificate(input-hash) dependencies before permanent rejection/failure tracking. Value-bearing legacy-mint rejection remains unchanged.
- Preserved existing result-token distribution, default-GNUS equality semantics, processing assignment/subtask behavior and other chain validators. No new processor policy, input-lock store, endpoint, dependency or schema was introduced.
