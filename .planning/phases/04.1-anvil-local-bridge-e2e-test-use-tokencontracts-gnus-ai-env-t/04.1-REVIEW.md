## Critical Issues

### CR-01: Catchup test seeds the WRONG event type — `safeTransferFrom` emits `TransferSingle`, not `BridgeOutInitiated`

**File:** `test/src/bridge_e2e/bridge_anvil_catchup_e2e_test.cpp:96,167,192-213,261-268`

**Issue:**
`SendOneAnvilBurn()` sends:

```
cast send <contract> "safeTransferFrom(address,address,uint256,uint256,bytes)" <sender> <sender> 0 <amount> 0x ...
```

This is an ERC-1155 self-transfer (`safeTransferFrom(self, self, tokenId=0, amount, "0x")`). It emits the ERC-1155 `TransferSingle(address,address,address,uint256,uint256)` event whose topic0 is `keccak256("TransferSingle(address,address,address,uint256,uint256)")`.

But the production catch-up scan in `src/account/GeniusNode.cpp:PerformStartupCatchupScan()` (lines 2913-2920, 2979-2982) builds its `eth_getLogs` EventFilter with topic0 = `kBridgeSourceBurnedSig` hash OR `kBridgeOutInitiatedSig` hash — and ONLY those two. The `accepted_topic0_hashes` primed in the test (line 310) likewise contains only `BridgeOutInitiated`.

Consequence: the catch-up scan will run, query `eth_getLogs` against Anvil, and get back ZERO matching logs for the 3 "pre-node burns" because none of them emit `BridgeOutInitiated`. The assertion at line 385-389 (`EXPECT_WAIT_FOR_CONDITION` for balance >= `initial + 3`) will therefore time out and the test will fail. The test's central invariant ("auto-mint path is the ONLY way the balance can increase") is vacuously unsatisfiable because no mintable event is ever observed.

This is compounded by `anvil_fixture.hpp:288-340` (`SendBridgeOutBurn`), whose Doxygen explicitly states that the prior `safeTransferFrom(self,self,...)` form "was NOT a burn on the hybrid ERC-20/ERC-1155 GNUS contract and reverted at gas estimate" — yet `bridge_anvil_catchup_e2e_test.cpp` reintroduces exactly that pattern. The two files in the same phase contradict each other on whether `safeTransferFrom` is a burn.

Per CLAUDE.md "the test IS the specification; if it exposes a real bug, fix the bug at its source" — but here the test itself is wrong, not the production code.

**Fix:**
Use the existing, already-correct `SendBridgeOutBurn()` helper from `anvil_fixture.hpp` (which calls the real `bridgeOut(uint256,uint256,uint256,bytes32,bool)` burn path) instead of the broken `safeTransferFrom` self-transfer. Concretely, replace the body of `SendOneAnvilBurn()` with:

```cpp
std::string BridgeAnvilCatchupE2ETest::SendOneAnvilBurn()
{
    // node_main is the destination; it is created in SetUpTestSuite before this is called.
    return sgns::test::anvil::SendBridgeOutBurn(
        s_anvil.RpcUrl(), kMintAmount, node_main->GetAddress() );
}
```

If the intent was for burns to seed BEFORE `node_main` exists, capture `node_main->GetAddress()` earlier or pass a pre-derived address; but the event signature must be `bridgeOut(...)` so the emitted topic0 is `BridgeOutInitiated`.

### CR-02: All three catchup-test nodes share the same private key/identity — PubSub/ValidatorRegistry collisions

**File:** `test/src/bridge_e2e/bridge_anvil_catchup_e2e_test.cpp:136,292,296,300`

**Issue:**
All three nodes are constructed with the identical constant
`kAnvilAccount0HexKey = "ac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80"`:

```cpp
node_main  = GeniusNode::New( s_configs[0], sgns::FromPrivateKey{ kAnvilAccount0HexKey } );  // line 292
node_proc1 = GeniusNode::New( s_configs[1], sgns::FromPrivateKey{ kAnvilAccount0HexKey } );  // line 296
node_proc2 = GeniusNode::New( s_configs[2], sgns::FromPrivateKey{ kAnvilAccount0HexKey } );  // line 300
```

A GeniusNode's libp2p PeerId, on-chain account address, and validator identity are all derived from this key. Three nodes with the same key will collide on:
- libp2p PeerId — the PubSub mesh at lines 323-325 connecting them will treat them as the same peer.
- account address — all three nodes will publish the same genesis validator address.
- validator slot — `Blockchain::SetAuthorizedFullNodeAddress(node_main->GetAddress())` at line 318 sets the same address that `node_proc1`/`node_proc2` also publish, defeating the 3-node cluster intent.

The sibling test `bridge_anvil_e2e_test.cpp:232-236,319` does this correctly with `kAnvilAccountHexKeys[i]` (3 distinct Anvil default keys), and `bridge_e2e_test.cpp` uses `s_eth_private_key` for node 0 and different derivations for nodes 1/2. The catchup test regressed on this pattern.

**Fix:**
Add the full Anvil default key list and use a distinct key per node, mirroring `bridge_anvil_e2e_test.cpp`:

```cpp
static inline constexpr const char *kAnvilAccountHexKeys[] = {
    "ac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80", // #0
    "59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d", // #1
    "5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a", // #2
};
// ...
node_main  = GeniusNode::New( s_configs[0], sgns::FromPrivateKey{ kAnvilAccountHexKeys[0] } );
node_proc1 = GeniusNode::New( s_configs[1], sgns::FromPrivateKey{ kAnvilAccountHexKeys[1] } );
node_proc2 = GeniusNode::New( s_configs[2], sgns::FromPrivateKey{ kAnvilAccountHexKeys[2] } );
```

### CR-03: `AnvilReplayRejection` dedup assertion is a no-op — always passes regardless of whether dedup works

**File:** `test/src/bridge_e2e/bridge_anvil_e2e_test.cpp:516-518`

**Issue:**
```cpp
const uint64_t balance_after_replay = s_nodes[0]->GetBalance( dest_addr );
EXPECT_EQ( balance_after_replay, s_nodes[0]->GetBalance( dest_addr ) )
    << "Balance should not increase for a replayed Anvil burn tx hash";
```

`balance_after_replay` is captured immediately before the `EXPECT_EQ`, and the comparator calls `GetBalance` again microseconds later. This assertion can only fail if the balance changes in between — which is itself NOT the dedup guarantee under test, and the two calls will almost always be equal even when dedup is broken (e.g. when the mint is still pending in the mempool, both calls return the same value).

Worse: the surrounding logic is inverted. The branch is entered when `!replay_rejected` (i.e. the second `MintTokens` SUCCEEDED — dedup FAILED to reject). Inside that branch the code should be asserting that the balance did NOT increase beyond the post-first-mint baseline (`balance_before_first + kMintAmount`), but instead it asserts that two near-simultaneous balance reads are equal. The test then unconditionally falls through to line 525 `EXPECT_TRUE(replay_rejected)` — so if `replay_rejected == false`, the only check that fires is the no-op `EXPECT_EQ`, and the test can spuriously report success when dedup is broken (the `<<` message is misleading but won't fail the test).

The sibling file `bridge_e2e_test.cpp:617-620` carries the same bug; this is a copy-paste defect.

**Fix:**
Capture a pre-second-mint baseline and compare against it after a wait, so a duplicate mint is actually detected:

```cpp
const uint64_t balance_before_replay = s_nodes[0]->GetBalance( dest_addr );

auto second_result = s_nodes[0]->MintTokens( kMintAmount, tx_hash,
    sgns::test::anvil::kSepoliaChainId, sgns::TokenID::FromBytes( { 0x00 } ),
    dest_addr, kReplayTimeout );

bool replay_rejected = second_result.has_error();
if ( !replay_rejected )
{
    // Give any erroneously-accepted duplicate time to settle, then assert no increase.
    EXPECT_WAIT_FOR_CONDITION(
        [&]() { return s_nodes[0]->GetBalance( dest_addr ) == balance_before_replay; },
        kReplayTimeout,
        "Balance must not increase from a replayed burn tx hash",
        nullptr );
}
EXPECT_TRUE( replay_rejected ) << "Replayed Anvil burn tx hash must be rejected by dedup cache";
```

### CR-04: `bridge_anvil_e2e_test.cpp` uses `FAIL()` instead of `GTEST_SKIP()` — violates D-16 "skip cleanly when Foundry binaries missing"

**File:** `test/src/bridge_e2e/bridge_anvil_e2e_test.cpp:264-267,280-283`

**Issue:**
D-16 (per the phase discussion log and the catchup test's own comment at line 221) mandates that tests "skip cleanly when Foundry binaries are missing." The sibling test `bridge_anvil_catchup_e2e_test.cpp:222-225` correctly implements this with `GTEST_SKIP()`. But `bridge_anvil_e2e_test.cpp` instead hard-fails:

```cpp
if ( !sgns::test::anvil::AnvilAvailable() || !sgns::test::anvil::CastAvailable() )
{
    FAIL() << "Foundry (anvil + cast) required: https://book.getfoundry.sh/getting-started/installation";
}
// ...
if ( !sgns::test::anvil::FundAccount0WithGnus( s_anvil.RpcUrl() ) )
{
    FAIL() << "Could not fund Anvil account #0 via impersonation of " << ...;
}
```

On any CI/dev agent without Foundry installed, or on a machine whose Sepolia RPC is being rate-limited (impersonation funding fails), this fixture will report a hard test FAILURE rather than SKIP. That pollutes CI signal with environment-driven failures and is exactly the scenario D-16 was written to avoid.

Note: the funding-failure case is slightly different — if Anvil started but funding failed, you might want a FAIL (because the environment is partially up). But the Foundry-missing case should clearly be SKIP. At minimum the first `FAIL()` must become `GTEST_SKIP()`.

**Fix:**
```cpp
if ( !sgns::test::anvil::AnvilAvailable() || !sgns::test::anvil::CastAvailable() )
{
    GTEST_SKIP() << "Install Foundry (anvil + cast): https://book.getfoundry.sh/getting-started/installation";
}
```

### WR-01: `EXPECT_WAIT_FOR_CONDITION` macro internally raises a FATAL failure — name lies about non-fatality

**File:** `test/testutil/wait_condition.hpp:117-139` (consumed by `test/src/bridge_e2e/bridge_anvil_e2e_test.cpp:456,500` and `test/src/bridge_e2e/bridge_anvil_catchup_e2e_test.cpp:385`)

**Issue:**
The macro is named `EXPECT_WAIT_FOR_CONDITION` (mirroring gtest's `EXPECT_*` = non-fatal convention), but `expectWaitForCondition()` at line 137 constructs the `TestPartResult` with `::testing::TestPartResult::kFatalFailure`. So `EXPECT_WAIT_FOR_CONDITION` aborts the current test body on timeout just like `ASSERT_WAIT_FOR_CONDITION`.

Direct impact in the reviewed files: in `bridge_anvil_e2e_test.cpp:456-459` and `bridge_anvil_catchup_e2e_test.cpp:385-389`, the author used `EXPECT_*` clearly intending "continue and let later assertions also run." If the wait times out, all subsequent assertions (e.g. the `EXPECT_GE(delta, ...)` catchall at lines 398 / 465) are skipped, hiding diagnostic output.

This is a project-wide macro defect (out of the file-under-review's direct scope) but it changes the semantics of every test using it. Flagging because the two reviewed test files rely on the false EXPECT-vs-ASSERT distinction.

**Fix:**
In `wait_condition.hpp:137`, change `kFatalFailure` to `kNonFatalFailure` for the `expectWaitForCondition` helper only (leave `assertWaitForCondition` fatal). The two helpers must differ in fatality to match their names.

### WR-02: Subprocess leak risk: `AnvilProcess::Start()` redirects child stdio with `freopen` but never restores parent FDs, and on Windows there is no `fork()`/`SIGTERM` path

**File:** `test/src/bridge_e2e/anvil_fixture.hpp:481-508,566-577`

**Issue:**
(a) `Start()` uses POSIX `fork()`+`execlp()` unconditionally. On `_WIN32` there is no `fork()` — `sys/types.h`, `sys/wait.h`, `unistd.h`, `csignal` (SIGTERM) are all unavailable. The header's `OpenCommandPipe` wrapper carefully handles `_WIN32`, but `AnvilProcess` does not. The CMakeLists builds this test on Windows (`if(WIN32)`), so `bridge_anvil_e2e_test.cpp` and the catchup test will fail to compile on Windows. This contradicts the header's own claim (lines 9-11) of cross-platform support.

(b) The child branch calls `freopen("/dev/null", ...)` on `stdin`/`stdout`/`stderr` (lines 493-495). `/dev/null` does not exist on Windows. The same platform-abstraction rule from CLAUDE.md ("Platform-specific code lives in `os/{OSX,Linux,Windows,iOS,Android}/Platform.hpp`") is violated.

(c) `Stop()` only reaps with `waitpid(..., 0)` (blocking, no timeout). If the Anvil child ignores `SIGTERM` (stuck RPC, hung fork), `Stop()` blocks forever — including in the destructor at line 456-462, which would hang test-suite teardown. There is no `SIGKILL` escalation, no `WNOHANG` + bounded retry.

**Fix:**
- Either gate `AnvilProcess` (and the two tests using it) to non-Windows platforms via CMake `if(UNIX)` guards and document this, or provide a Windows implementation using `CreateProcess`+`TerminateProcess` consistent with the project's `os/Windows/Platform.hpp` pattern. The current "works on Apple/Linux only" reality must not be hidden behind a header that claims portability.
- In `Stop()`, escalate: `kill(pid, SIGTERM)` then poll `waitpid(pid, &status, WNOHANG)` for a bounded grace period (e.g. 5 seconds via `waitForCondition`), then `kill(pid, SIGKILL)` + final `waitpid`. This prevents a hung child from hanging test teardown.

### WR-03: `FundAccount0WithGnus` trims/checks balance output but does not reject negative-looking or overflow values; uses `has_nonzero` byte-scan instead of numeric compare

**File:** `test/src/bridge_e2e/anvil_fixture.hpp:390-424`

**Issue:**
The balance check at lines 407-421 scans the string for any char in `'1'..'9'` and treats presence as success:

```cpp
bool has_nonzero = false;
for ( char c : balance_out )
{
    if ( c >= '1' && c <= '9' ) { has_nonzero = true; break; }
}
```

This incorrectly accepts output like `"abc9def"` or `"[\n  9\n]"` (any stray digit) as a valid non-zero balance. `cast call` on error can return JSON or error text containing digits (e.g. `"Error: ... code -32000"`). A real non-zero balance check should parse the leading integer.

Also, if `balance_out` is `"0"` followed by nothing, the function correctly returns false — but if it is `"0\n0"` (some malformed echo), `has_nonzero` stays false and the function returns false even though that is an environment error, not a "still zero" condition. The diagnostic message at line 419 will mislead.

**Fix:**
Parse the output with `std::stoull` (trim whitespace first) and compare `> 0`:

```cpp
std::string trimmed = balance_out;
// trim leading/trailing whitespace
while ( !trimmed.empty() && std::isspace( static_cast<unsigned char>( trimmed.front() ) ) ) trimmed.erase( trimmed.begin() );
while ( !trimmed.empty() && std::isspace( static_cast<unsigned char>( trimmed.back() ) ) ) trimmed.pop_back();
uint64_t bal = 0;
try { bal = std::stoull( trimmed, nullptr, 10 ); }
catch ( ... ) { spdlog::warn( "anvil_fixture: balanceOf returned non-numeric: {}", trimmed ); return false; }
if ( bal == 0u ) { spdlog::warn( "anvil_fixture: account #0 balance still zero after funding" ); return false; }
```

### WR-04: `RunShellCapture` / `SendBridgeOutBurn` / `SendOneAnvilBurn` shell-inject command construction with untrusted-looking concatenation

**File:** `test/src/bridge_e2e/anvil_fixture.hpp:140-156,303-340,319-323` and `test/src/bridge_e2e/bridge_anvil_catchup_e2e_test.cpp:195-198`

**Issue:**
`SendBridgeOutBurn` builds a shell command by string-concatenating `kSepoliaBridgeContractLower`, `amount`, `kDestChainId`, `dest_bytes32`, `dest_y_odd`, `kAnvilAccount0Address`, and `anvil_rpc_url` into a `cast send ...` line passed to `popen("r")`. The `cast_cmd` is then handed to `/bin/sh -c` by `popen`.

Currently every input is a hardcoded constant or a derived hex string (`dest_bytes32` is validated as 0x + 64 hex chars by `BridgeDestinationFromSgnsAddress`), and `anvil_rpc_url` is constructed as `http://127.0.0.1:<port>` so there is no immediate exploit. But the function signature accepts an arbitrary `anvil_rpc_url` and `sgns_destination_128` from callers; if a future test ever passes an RPC URL containing a shell metacharacter (`;`, backtick, `$(...)`) or a destination with embedded quotes, this is a command-injection vector. The CLAUDE.md testing discipline doesn't make an explicit rule here, but the pattern is fragile.

Additionally, the use of `2>&1` mixed into the command (line 323) means RPC error text is indistinguishable from successful JSON in `output`, which is why `ParseTxHashFromCastJson` is needed — and why a malformed error containing `"transactionHash":"0x...` could spoof success.

**Fix:**
- Replace `popen` with `execvp`-style child-process invocation (`fork`+`execvp` with argv array) so no shell interpretation occurs. This also aligns with the project's existing `AnvilProcess::Start()` pattern.
- Alternatively, validate `anvil_rpc_url` against a strict regex (`^https?://[0-9a-zA-Z.:/_-]+$`) before concatenation, and pass `--rpc-url` via an environment variable or argv rather than string interpolation.

### WR-05: `BridgeEventTopic0()` is recomputed on every call and depends on a non-trivial keccak; no caching despite being a pure constant

**File:** `test/src/bridge_e2e/anvil_fixture.hpp:75-79`

**Issue:**
`BridgeEventTopic0()` calls `eth::abi::event_signature_hash(...)` (keccak256 over the canonical signature) followed by `rlp::base::parse::hex_bytes(...)` every time it is invoked. It is invoked at least 4 times per test-suite run (once per `accepted_topic0_hashes` initializer in each fixture). The function is declared `static inline` so the compiler MAY inline-and-fold repeated calls within a single TU, but cross-TU calls (one in `bridge_anvil_e2e_test.cpp`, one in `bridge_anvil_catchup_e2e_test.cpp`) cannot be folded. Result: redundant keccak work and a subtle performance/clarity issue.

More importantly, the function returns a fresh `std::string` each call. If the underlying `kBridgeOutInitiatedSig` ever changes, every call site recomputes — fine — but if a future caller stored the result in a `const char*` it would dangle. The interface invites misuse.

**Fix:**
Make it a function-local static so the keccak runs exactly once per process:

```cpp
static inline const std::string &BridgeEventTopic0()
{
    static const std::string kTopic0 = []{
        const auto hash = eth::abi::event_signature_hash( std::string( sgns::kBridgeOutInitiatedSig ) );
        return rlp::base::parse::hex_bytes( hash.data(), hash.size() );
    }();
    return kTopic0;
}
```

Returning a reference makes the lifetime contract explicit.

### WR-06: `WaitForReady` heap-allocates a `std::string` solely to capture output it then discards — leak risk on exception

**File:** `test/src/bridge_e2e/anvil_fixture.hpp:531-549`

**Issue:**
```cpp
std::string     *ready = new std::string();
bool result = waitForCondition( [&cmd, ready]() { ... *ready = out; ... }, timeout, nullptr, ... );
delete ready;
```

The `ready` heap string exists only to ferry the last poll's output out of the lambda, but the value is never used after the loop — the function just returns `result`. The bare `new`/`delete` pair leaks if `waitForCondition` (or the lambda) ever throws. This is gratuitous complexity.

**Fix:**
Use a stack string captured by reference; `waitForCondition` already provides no post-hoc read of `ready`:

```cpp
std::string ready;
bool result = waitForCondition(
    [&cmd, &ready]() {
        int exit_code = -1;
        std::string out = RunShellCapture( cmd, exit_code );
        if ( exit_code == 0 && !out.empty() ) { ready = std::move( out ); return true; }
        return false;
    },
    timeout, nullptr, std::chrono::milliseconds( kAnvilPollIntervalMs ) );
```
