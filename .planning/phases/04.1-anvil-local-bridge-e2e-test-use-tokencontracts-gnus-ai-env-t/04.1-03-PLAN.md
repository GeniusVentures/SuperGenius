<objective>
Apply the D-19/D-20/D-21/D-23/D-03 catchup watcher RPC strategy corrections to production code: replace `scan_depth` with `start_block` (genesis scan), add exponential backoff to `RpcHttpTransport::call()`, and fix the Sepolia fallback URL. These are the production-side prerequisites that Plan 04.1-02's three catchup E2E scenarios depend on.

Purpose: The prior catchup design capped the first scan at `scan_depth=10000` blocks back from latest and silently dropped any RPC error. D-19 removes the depth cap (archive `eth_getLogs` with event-filter topics is server-side filtered, so full-history scans are cheap). D-20 adds `start_block` so tests can inject the Anvil fork block and scan only post-fork blocks. D-21/D-23 require retry-with-backoff on transient RPC failures so a single timeout does not lose an entire scan chunk. D-03 corrects the public Sepolia fallback URL from `publicnode.com` (403 on archive queries without a token) to `sepolia.drpc.org` (archive-capable, no API key).

Output: Modified `bridge_catchup_watcher.hpp/.cpp` (Config field swap), `GeniusNode.hpp/.cpp` (constant removal), `anvil_fixture.hpp` (URL fix), `rpc_http_transport.hpp/.cpp` (retry loop).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-13 | Tampering | Retry loop on transient failure | mitigate | Bounded by options_.retry_count (default 3) with exponential backoff capped at kMaxRetryBackoffMs (8s). A misbehaving RPC endpoint cannot trigger an unbounded retry storm. Total worst-case delay per call: 1+2+4 = 7s backoff + 3x timeout. |
| T-04.1-14 | Denial of Service | Exponential backoff without cap | mitigate | kMaxRetryBackoffMs (8s) caps the doubled backoff so a high retry_count cannot produce multi-minute delays. The `(1ull << attempt)` shift is bounded by retry_count (typically 3), so no integer overflow risk. |
| T-04.1-15 | Information Disclosure | Retry logging | accept | If a logger is added, retry attempts log the attempt number and backoff delay — no request/response bodies logged. If no logger is added (preferred minimal change), no information is emitted. |
| T-04.1-16 | Tampering | 4xx classified as permanent (no retry) | mitigate | classify_http_status returns kPermanentFailure for HTTP 400-499, causing immediate bail. This prevents retrying auth failures (401/403) or bad requests (400) which would never succeed on retry. Only 5xx and connection-level failures retry. |
| T-04.1-17 | Spoofing | Sepolia fallback URL change (D-03) | mitigate | drpc.org is a well-known public RPC aggregator. TLS verification (verify_peer default true) prevents MITM. The URL is a constexpr constant, not user-input-derived. |
