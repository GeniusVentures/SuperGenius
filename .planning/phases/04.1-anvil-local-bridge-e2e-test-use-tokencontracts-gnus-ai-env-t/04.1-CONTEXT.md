<decisions>
## Implementation Decisions

### Anvil Lifecycle
- **D-01:** Test fixture (`SetUpTestSuite`) starts Anvil as a subprocess: `anvil --fork-url <SEPOLIA_RPC> --port <dynamic_port>`. Killed in `TearDownTestSuite`.
- **D-02:** Forks Sepolia (not mainnet) — bridge contract already deployed at `0x9af8050220D8C355CA3c6dC00a78B474cd3e3c70`.
- **D-03:** Sepolia RPC URL for `--fork-url` comes from `chains_config.json` (Phase 1 wiring) or `RPC_SEPOLIA` env var override — same source as production code. Fallback endpoint: `https://sepolia.drpc.org` (public, no API key required, supports archive `eth_getLogs`). Previously used `ethereum-sepolia-rpc.publicnode.com` which returns 403 for archive queries without a personal token.
- **D-04:** Test polls Anvil's JSON-RPC (`eth_blockNumber`) to confirm it's ready before proceeding. Configurable timeout with `wait_condition.hpp`.

### Anvil Default Keys (no .env dependency)
- **D-05:** Use Anvil's deterministic default keys — 10 accounts, each with 10,000 ETH on the fork. Private keys are well-known (derived from mnemonic `test test test test test test test test test test test junk`).
- **D-06:** No `.env` file needed — no external dependency on `../TokenContracts/gnus-ai/`. The test is fully self-contained.
- **D-07:** The test uses Anvil default account #0 (private key `0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80`, address `0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266`).

### GNUS Token Funding
- **D-08:** On the forked Sepolia, the default Anvil account has 0 GNUS tokens. The test must fund it before sending the bridge burn transaction.
- **D-09:** Funding approach: use Anvil's `anvil_impersonateAccount` to impersonate a Sepolia GNUS holder, then `cast send` GNUS tokens to the Anvil default account. Alternatively, use `anvil_setBalance` on the GNUS token contract storage slot — Claude's discretion based on feasibility.
- **D-10:** If impersonation + transfer doesn't work, the fallback Sepolia-direct test path (D-14) uses the original Phase 4 approach with `PRIVATE_KEY` env var.

### evmrelay + Anvil WebSocket
- **D-11:** Anvil supports JSON-RPC and WebSocket subscriptions (`eth_subscribe` for logs/newHeads) but NOT p2p (no RLPx, no discv4, no ETH wire protocol). evmrelay's `EthWatchService` connects via WebSocket — point it directly at `ws://127.0.0.1:<anvil_port>`.
- **D-12:** If evmrelay's `EthWatchService` cannot consume Anvil WebSocket events (subscription format mismatch, missing p2p handshake expectation), the test logs the limitation and falls through to the Sepolia-direct path.

### Test Structure
- **D-13:** Reuse Phase 4's 3-node GTest fixture pattern: `BridgeE2ETest` or new `BridgeAnvilE2ETest` in `test/src/bridge_e2e/`, `SetUpTestSuite`/`TearDownTestSuite`, PubSub `AddPeers`.
- **D-14:** Two test paths, gated by availability:
  - **Path A (Anvil):** Preferred — local, fast, deterministic. Guarded by `GTEST_SKIP` if `anvil` binary not found. Burn trigger via `cast send` to `localhost:<anvil_port>` using Anvil default key #0.
  - **Path B (Sepolia):** Fallback — matches Phase 4 original approach. Guarded by `GTEST_SKIP` if `PRIVATE_KEY` env var not set (or `RUN_E2E_BRIDGE` not set, per Phase 4 D-03).
- **D-15:** Port allocation: use a dynamic/high port to avoid conflicts. Anvil started with `--port 0` or test fixture picks an available port.
- **D-16:** `cast` binary (Foundry) must be installed. Test checks and skips with clear message if missing — same as Phase 4 D-10.

### Verification
- **D-17:** Same assertions as Phase 4 (D-13): (a) `MintTransactionV2` created with correct chain_id/amount/token_id/burn_tx_hash, (b) UTXO consensus produced certificate, (c) minted UTXO in recipient's set.
- **D-18:** Negative tests (Phase 4 D-14/D-15): replay rejection, missing endpoints, invalid receipt logs — can use mock RPC transport (Phase 5) for speed, or run against Anvil with deliberate misconfiguration.

### BridgeCatchupWatcher RPC Strategy
- **D-19:** Remove `scan_depth` from `BridgeCatchupWatcher::Config`. On first poll, start from block `0` (genesis). `eth_getLogs` with event-filter topics returns only matching burn events — filtered server-side, so full-history queries are cheap (most chunks return `[]`). No need for a depth guard.
- **D-20:** Add `start_block` field to `BridgeCatchupWatcher::Config` (default `0`). Production nodes scan from genesis. Tests inject the fork block to scan only post-fork blocks where local `cast send` burns exist.
- **D-21:** JSON-RPC error responses (e.g. `{"error":{...}}`) are NOT silently skipped. Transient failures (timeout, 503) use retry-with-backoff. The 403 from `publicnode.com` is a test configuration issue, not a code bug — fixed by D-03's fallback URL change.
- **D-22:** Fork block for test injection: the test queries Anvil's `eth_blockNumber` BEFORE sending burns. The returned block is the Sepolia fork block. Tests B and C inject this via `Config::start_block` so the watcher only scans post-fork blocks.
- **D-23:** `RpcHttpTransport::call()` currently has no retry/backoff — any error returns `nullopt`. Exponential backoff must be added. Two approaches: (A) add retry to `RpcHttpTransport::call()` directly (benefits all callers), or (B) switch the catchup watcher to use `RpcEndpointPool` which already has exponential backoff (`{1s, 2s, 4s, ...}` capped at `kMaxBackoff`). Claude's discretion on approach.
- **D-24:** `last_block_per_chain_` (in-memory only) must be persisted to disk so node restarts don't re-scan from block `0`. Use DI so tests can inject/reset the persisted value. This is a follow-up — NOT required for the immediate test fix.
- **D-25:** Watcher querying the upstream RPC directly (not through Anvil forwarding) is not needed. Anvil fork forwarding + a proper archive-capable fork URL handles all cases. Test-only concern.

- **D-26:** Three catchup E2E test scenarios:
  - **Test A (full scan):** Watcher scans from block `0` through Anvil fork. May return zero or more Sepolia burns (depends on fork state). Both outcomes are valid — test verifies the scan completes without error and any found burns are correctly minted.
  - **Test B (post-fork only):** Watcher started with `start_block` set to the Anvil fork block. Only scans post-fork blocks containing local `cast send` burns. Verifies the exact set of local burns is discovered.
  - **Test C (two-phase):** Phase 1: scan block `0` to fork's last pre-fork block. Phase 2: scan fork block `-5` to current. Verifies both phases independently discover their respective burns and the watcher's `last_block_per_chain_` correctly bridges the gap.

### Claude's Discretion
- Anvil subprocess management (fork/exec `anvil`, signal handling, port selection, readiness polling)
- Anvil default key selection (which account #0-9 to use)
- GNUS token funding mechanism (impersonation vs. storage manipulation vs. other)
- evmrelay WebSocket endpoint configuration for Anvil
- Test fixture class name and file organization
- Whether Anvil and Sepolia paths share one fixture or use separate test cases

</decisions>

<specifics>
## Specific Ideas

- Anvil's default account #0 (`0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266`) is the sender — its private key is hardcoded in the test (public knowledge, test-only)
- The Anvil fork carries Sepolia's full state, so the bridge contract at `0x9af8050220D8C355CA3c6dC00a78B474cd3e3c70` is already deployed with its current storage
- GNUS token funding: `anvil_impersonateAccount` a known Sepolia GNUS holder → transfer GNUS to the Anvil default account → stop impersonating. Clean and works with standard ERC-20 `transfer`.
- Fallback Sepolia path is the same as Phase 4 — no new infrastructure, just a second test case in the same file
- Not CI-runnable (requires `anvil` and `cast` binaries, plus Sepolia RPC access for the fork)
- Port selection: use a fixed high port like `8545` (Anvil default) or pick dynamically — if another Anvil is running, dynamic is safer
