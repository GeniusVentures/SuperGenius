- **Zero manual MintTokens() in the test body.** The entire purpose of the plan is to prove the auto-mint path. ## Issues Encountered

### Pre-existing build break blocks full link verification (out of scope)

A fresh `ninja bridge_anvil_catchup_e2e_test` link fails because of a pre-existing `shared_future`/`Subscription` type mismatch in THREE untouched dependency-chain files:

- `src/account/AccountMessenger.cpp` (lines 64, 79)
- `src/crdt/globaldb/pubsub_broadcaster_ext.cpp` (lines 108, 347 — via the CRDT unity build)
- `src/blockchain/Consensus.cpp` (line 81)

All three share the same root cause: `GossipPubSub::Subscribe(...)` returns `shared_future<shared_ptr<sgns::ipfs_pubsub::GossipPubSub::Subscription>>`, but the assignment targets expect a different `shared_future<shared_ptr<...>>` type. The libc++ in Xcode's MacOSX26.2.sdk rejects the conversion; older libc++ accepted it. This is NOT a regression from this plan — a clean rebuild of the EXISTING Plan 04.1-01 `bridge_anvil_e2e_test` target fails the same way today. The main checkout's `build/OSX/Debug` has stale working `.o` files that mask the break.

Per executor scope-boundary rule, these are out of scope (none of the files are touched by this plan). They are logged in `deferred-items.md` with full root-cause analysis and a suggested follow-up task. Verification performed instead:

1. `cmake .. -DBUILD_TESTING=ON` succeeds — the new CMake target configures cleanly.
2. `ninja test/src/bridge_e2e/CMakeFiles/bridge_anvil_catchup_e2e_test.dir/bridge_anvil_catchup_e2e_test.cpp.o` succeeds (exit 0, zero warnings) — the new test source compiles cleanly against all project headers using the exact compile flags of the existing `bridge_anvil_e2e_test` target.
3. `-fsyntax-only` compile of the new test source: clean (return 0) after the enum fix.
4. All 16 static acceptance-criteria greps pass (see Self-Check).

### Worktree submodule initialization
