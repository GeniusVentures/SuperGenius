# Phase 04.1 Plan 02: D-26 Three-Scenario Catchup E2E Tests Summary

Adapted the D-26 three-test-scenario catchup E2E test file to use the DI approach (TransportFactory injection in Config) instead of `friend class`, per user preference. Tests B and C now use the public `startWatching()`/`stopWatching()` API instead of calling private `poll_once()`.

## What Was Built

### Test File Restructuring
- **Three D-26 scenarios** replace the old single `StartupCatchupScanAutoMintsHistoricalBurns` test:
  - `FullScanFromGenesisNoErrors` (Test A): Production node-owned watcher scans from genesis. Verifies scan completes without error. No specific burn count assertion — Sepolia-origin burns are bonus.
  - `PostForkScanMintsLocalBurns` (Test B): Standalone watcher with `start_block = s_fork_block`. Verifies `GetLastProcessedBlock` advances past fork and all `kNumCatchupBurns` local burns are discovered.
  - `TwoPhaseScanBridgesGap` (Test C): Two standalone watchers — Phase 1 (`start_block=0`) and Phase 2 (`start_block=s_fork_block-5`). Verifies gap-bridging and independent burn discovery.
- **Fork-block capture** (D-22): `cast block-number` query in `SetUpTestSuite` BEFORE pre-node burns, stored as `s_fork_block`.
- **Standalone watcher builder helpers**: `MakeStandaloneChainsProvider`, `MakeStandaloneRpcResolver`, `MakeCountingBurnProcessor` in anonymous namespace.

### DI Adaptation (from Plan 03 + this plan)
- `BridgeCatchupWatcher::Config::TransportFactory` field (committed in Plan 03) replaces `friend class BridgeAnvilCatchupE2ETest`.
- Tests B and C use `startWatching()` → `ASSERT_WAIT_FOR_CONDITION` on `GetLastProcessedBlock` → `stopWatching()` instead of `poll_once()`.
- Zero `friend class` declarations in production code.

## Deviations from Plan

### DI instead of friend class (user-directed)
- **Plan truth #8** says "BridgeCatchupWatcher grants friend access to BridgeAnvilCatchupE2ETest so poll_once() can be driven deterministically…"
- **User chose DI**: `TransportFactory` in Config (committed in Plan 03) + public `startWatching()`/`stopWatching()` API for standalone watchers in tests.
- **Impact**: Acceptance criteria `grep -c "friend class" >= 1` → now 0. `grep -c "poll_once" >= 3` → now 0. Replaced by `grep -c "startWatching" >= 6` and `grep -c "stopWatching" >= 3`.
