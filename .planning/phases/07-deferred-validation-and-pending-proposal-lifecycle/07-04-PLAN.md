<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer proposal -> ConsensusManager | Untrusted remote proposal data enters local validation and pending storage. |
| dependency event -> pending retry | Local CRDT/certificate arrivals wake pending proposals and can trigger repeated validation. |
| ConsensusManager -> TransactionManager cleanup | Local expiry/certification callbacks change transaction tracking state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | pending proposal pool | mitigate | Reuse Plan 03 admission/capacity checks; expiry frees capacity deterministically. |
| T-07-02 | Denial of Service | retry scheduler and dependency wakeups | mitigate | Enforce D-05 bounded backoff and D-06 minimum retry interval on dependency-triggered wakeups. |
| T-07-03 | Tampering / Elevation of Privilege | local Approval vote retry path | mitigate | Route every retry approval through existing proposal/slot state and assert no duplicate self-vote. |
| T-07-04 | Tampering | dependency key indexing | mitigate | Wake only typed `PendingDependencyKey` values and test predecessor-certificate wakeups by key type and value. |
| T-07-05 | Repudiation / Integrity | transaction state on inconclusive expiry | mitigate | Fire cleanup callbacks only for TTL/timeout expiry so Plan 05 can classify inconclusive state separately from proven invalidity. |
</threat_model>
