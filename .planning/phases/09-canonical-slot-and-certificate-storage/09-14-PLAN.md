<interfaces>
`ChangeTransactionState(CONFIRMED)` currently writes `tx_processed_m` and a logical GlobalDB `/bridge/executed/...` marker before `ParseTransaction`.
`ParseMintTransaction` currently calls `PutProducedUTXOs` and then `ConsumeUTXOs`; each operation mutates memory before a separate `StoreUTXOs` batch.
`UTXOManager::StoreUTXOs` already serializes `SGTransaction::UTXOEntryRecord` values and commits a RocksDB `BufferBatch`, but it commits one post-mutation address snapshot at a time.
`PutUTXO`, `DeleteUTXO`, `ConsumeUTXOs`, and `SetUTXOs` release `utxos_mutex_` before calling `StoreUTXOs`. Today `StoreUTXOs` queries old keys and constructs a batch before taking only a short shared state lock, so two stores can commit snapshots out of preparation order. Atomic application cannot be safe merely by holding `utxos_mutex_`; a previously prepared ordinary batch could otherwise land afterward and revert its durable effects while leaving the application record present.
`GlobalDB::Put` is a logical CRDT operation and cannot participate in the raw RocksDB batch used by UTXOManager. This plan therefore removes the old GlobalDB completion authority instead of claiming a cross-store atomic batch.
The new authoritative key is burn-keyed and outside the `/utxo/` scan namespace: `/bridge/application/v1/&lt;chain&gt;:&lt;burn_hash&gt;:&lt;receipt_index&gt;`.
</interfaces>
