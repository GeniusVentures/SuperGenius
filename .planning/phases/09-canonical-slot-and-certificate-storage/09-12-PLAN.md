Refactor `CRDTDataFilter::FilterDelta` to evaluate every matching delta filter against the unchanged original delta, record each matching filter's decision/pattern/dependency, and sanitize a separate returned delta. Remove every element and tombstone matching a Reject namespace. After sanitation, if any retained element or tombstone still matches a valid RetryDependency namespace, return `FilteredDeltaResult{sanitized_delta, RetryDependency, dependency_cid}`; do not run legacy element filters. Thus Reject has terminal authority only over its own namespace and cannot convert a retained stalled namespace into mergeable data.

Define multiple-result semantics explicitly. RetryDependency without a parseable dependency remains terminal Reject for that filter namespace. Multiple retained RetryDependency filters naming the same canonical dependency may coalesce into one retry. If retained retry filters name distinct dependencies, fail closed by sanitizing every affected retry namespace and returning Reject with no dependency; never choose one CID nondeterministically or park data whose other dependency was discarded. If sanitation removes all retry-matched data, return Reject for the rejected-only remainder and allow unrelated sanitized data to follow the existing merge behavior.

Keep `CrdtDatastore::ProcessJobIteration`'s pre-merge guard strict: a returned RetryDependency with its canonical CID exits before `MergeDataFromDelta`, `dagSyncer_->addNode`, block deletion, head update, or callbacks. The external-root delta must contain rejected `/reject/attack`, stalled `/retry/slot`, and unrelated `/unrelated/live`. Assert the rejected key is absent, the stalled key and unrelated co-packaged data remain invisible while the root is parked, the original dependency CID is retained, and no new-element callback fires. After the dependency flag becomes ready and the retry deadline is advanced, assert `/retry/slot` and `/unrelated/live` merge once, `/reject/attack` remains absent, and callbacks occur exactly once. Make close initiation and completion distinct and idempotent. Add a worker-safe `RequestClose()` operation returning one shared completion barrier (for example `std::shared_future&lt;void&gt;`) and keep `CancelAndCloseNow()` as the synchronous external convenience that requests close and waits for that same barrier. Exactly one owned coordinator, never a detached thread, performs `WaitForWorkersToExit`, parked-root cleanup, queue/job/head drain, sets `started_ = false`, records a zeroed synchronized end snapshot, transitions lifecycle to Closed, and fulfills the barrier.
