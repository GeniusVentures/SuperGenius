<interfaces>
Current DAG, handle-next, and rebroadcast workers promote `weak_ptr&lt;CrdtDatastore&gt;`. The safety problem is not promotion itself: it is retaining a promotion across a loop or blocking wait, which can keep ownership circulating among workers.
Both callbacks passed to `CrdtSet` in `CrdtDatastore::New` also lock a weak pointer before calling `PutElementsCallback` or `DeleteElementsCallback`. That scoped ownership is required so releasing an external owner from callback code cannot destroy the callback's target mid-call.
If the sole external owner is reset inside one of those callbacks, the callback's scoped strong owner remains. The weak pointer therefore remains lockable during that callback by design. The true zero-count transition occurs only when the last scoped worker/callback owner returns or completes its bounded operation.
`RequestClose` currently launches a member `closeCoordinatorThread_` with raw `[this]`; `CancelAndCloseNow` returns without waiting on an internal worker; the destructor calls it. Final deletion must be separated from whichever thread releases the final scoped strong owner.
`CrdtDatastore` has a private constructor and production construction goes through `CrdtDatastore::New`, allowing one mandatory custom deleter and separately allocated shutdown runtime to be installed coherently.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External owner → callback-local owner | External release must not invalidate a callback that already locked the weak pointer |
| Worker loop → blocking wait | Scoped datastore ownership must end before idle waiting so workers cannot perpetually hand ownership around |
| Shared control block → custom deleter | Actual zero-count release may occur on a worker, but that thread may only enqueue finalization |
| Reaper → datastore members | Finalization must stop/wake callbacks and workers, drain them, and fulfill the truthful barrier before delete |
| Static service teardown → deferred deletes | Process exit must not abandon queued allocations or invoke a stopped service |
