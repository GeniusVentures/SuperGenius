<objective>
Establish the project's first libFuzzer+ASan build tier (`-DSGNS_FUZZING=ON`, fully excluded from
normal CI) and ship three harnesses covering the phase's selected fuzz targets: burn-event
ABI/log decoding (`eth::abi::decode_log_data`), the burn-event value parser
(`BridgeRelayer::ParseBurnEventValues`), and transaction deserialization
(`MintTransactionV2::DeSerializeByteVector`).

Purpose: These three functions are the datapath's only points that parse untrusted, attacker-
reachable bytes (on-chain log data, raw transaction bytes). Per 08-RESEARCH.md Pitfall 4, unchecked
buffer indexing on fuzzer-controlled input is the real vulnerability class to catch — this plan
turns that into an automated, CI-integrated (smoke-run) verification.
Output: `fuzz/` top-level directory (3 harnesses + CMakeLists.txt + seed corpus), plus
`addfuzztarget()` in `cmake/functions.cmake` and the `SGNS_FUZZING` option wired from
`test/CMakeLists.txt`.
</objective>

`outcome::result<BurnEventParams> BridgeRelayer::ParseBurnEventValues(const std::vector<eth::abi::AbiValue> &values)`
(`src/account/BridgeRelayer.hpp`/`.cpp`): requires `values.size() >= 6` (kExpectedMinParams);
index 1 must be `intx::uint256` (token_id), index 2 must be `intx::uint256` (amount), index 5
is the destination — either `eth::codec::ByteBuffer` sized exactly 64 bytes (v1) or
`eth::codec::Hash256` (v2, requires index 6 to be `bool` destinationYOdd). Uses
`std::holds_alternative` checks before every `std::get` — already safe; harness must still exercise
every branch (v1 ByteBuffer wrong-length, v2 missing index 6, v2 present) via corpus seeds.

`using AbiValue = std::variant<codec::Address, intx::uint256, codec::Hash256, bool,
codec::ByteBuffer, std::string>;` (`evmrelay/include/eth/abi_decoder.hpp`).

`rlp::Result<std::vector<AbiValue>> decode_log_data(const codec::ByteBuffer &data,
const std::vector<AbiParam> &params) noexcept;` — decodes non-indexed ABI log data fields given a
raw byte buffer and an ordered parameter-kind list. `AbiParamKind` enum includes `kAddress`,
`kUint`, `kBytes32`, `kBool` (see `abi_decoder.hpp` for the full list — read the file directly for
the exact enum values before writing the harness's fixed `params` vector, which must match the
burn event's actual non-indexed field layout: tokenId(uint), amount(uint), destChainID(uint),
sgnsDestination(bytes32), destinationYOdd(bool) — 5 non-indexed params minimum per the v2
`bridgeOut` signature in CONTEXT.md's Solidity excerpt).

`std::shared_ptr<MintTransactionV2> MintTransactionV2::DeSerializeByteVector(const std::vector<uint8_t> &data)`
(`src/account/MintTransactionV2.hpp:39`, impl `MintTransactionV2.cpp:93`) — returns nullptr or
throws on malformed input; read the `.cpp` implementation before writing the harness to confirm
whether it throws (harness must catch) or returns nullptr (harness checks return value) on invalid
data.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| On-chain log bytes -> `decode_log_data`/`ParseBurnEventValues` | Attacker-controlled if bridge contract or RPC endpoint is compromised |
| Serialized transaction bytes -> `MintTransactionV2::DeSerializeByteVector` | Attacker-controlled if a peer sends a malformed proposal |
| Seed corpus files checked into repo | Low — repo-controlled, requires PR review to alter |
