Close VERIFICATION.md gap 3 (and the wiring half of gaps 1/4): GeniusNode consumes the
NetworkRegistry's cached membership as the gossip-ingest enforcement — the descoped half of
15-05, implemented per the owner direction (deferred-items.md §3) as SuperGenius-side filtering
instead of a GossipPubSub allow-list.

Wiring (three edits at/around the existing construction site, GeniusNode.cpp:1055-1083):
1. After `network_registry_ = network_registry_result.value();` install the 15-11 filter on the
   node's single GlobalDB broadcaster: `tx_globaldb_->GetBroadcaster()->SetMembershipFilter(
   sgns::networkregistry::MakeNetworkMembershipFilter( network_registry_ ))`. Every inbound gossip
   message entering CRDT replication is then authorized against the registry's cached membership
   (fail-closed). This also covers the replicated ingest of all job/task/result data, which flows
   through the same broadcaster (single GlobalDB, verified: secure_crdt_ wraps tx_globaldb_ at
   GeniusNode.cpp:830).
2. Pass `tx_globaldb_` as NetworkRegistry::New's trailing `global_db` argument so the cache
   refreshes live from network-registry CRDT changes (BurnConfig pattern) — this is what makes
   runtime membership widening effective at the enforcement point (proven at component level by
   15-11's MembershipWideningAdmitsNewPeerAtRuntime). This wiring was deliberately deferred in
   15-05 ("enable when the allow-list consumer lands") — the consumer now exists, and 15-09 fixed
   WR-02 so the refresh thread does not busy-spin once started (hard dependency).
3. Teardown: `ShutdownNodePolicyServices` clears the broadcaster filter BEFORE resetting
   network_registry_ (the weak_ptr-backed predicate would deny-all anyway — fail-closed — but the
   explicit clear keeps the public-node-after-teardown state clean and testable).

Purpose: D-07's consumption side becomes real in the node: membership is consulted on every
inbound replicated message. Output: wiring + test accessor + binding scenes.
