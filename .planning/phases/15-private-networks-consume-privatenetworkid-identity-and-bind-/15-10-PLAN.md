<objective>
Close VERIFICATION.md gap 6 — the CR-01 (Critical) + WR-01 fail-open chain in private-network
provisioning:

Today `WriteNetworkConfig`'s escaping loop (GeniusNode.cpp:225-247) handles only `\\` and `"`, so
the canonical go-ipfs swarm-key text (`/key/swarm/psk/1.0.0/\n/base16/<64 hex>\n` — the format the
vendored `Psk::fromSwarmKeyText` explicitly parses) is written with raw newline bytes: illegal in
JSON strings. On the next start `LoadNetworkConfig` hits the parse-error branch (:1599-1603),
logs an error, and returns settings with `valid == true` — no network_key, no private_network_id.
A node the operator provisioned PRIVATE boots fully PUBLIC: no PSK boundary on either host, public
validator-registry identifiers, public CRDT paths — bypassing every identity validation added this
phase (they run only after a successful parse).

Fix (per the 15-REVIEW.md CR-01/WR-01 fix sketches, which are binding for this plan):
1. Writer: escape all JSON string-unsafe characters (\\n, \\r, \\t, \\b, \\f, other <0x20 as \\u00XX).
2. Loader: a file that EXISTS but is unparseable (or not an object) fails closed —
   `settings.valid = false` — so InitNetwork aborts exactly like a malformed private_network_id.
3. The missing-file branch stays public-default BY DESIGN: an absent config is the documented
   public-node provisioning state (D-01 "absent id → public node, unchanged"; pinned by the
   existing AbsentKeysKeepPublicNodeBehavior scene). The exploit chain is closed because the
   writer now always emits parseable JSON and any corruption of an existing file is fatal.

Purpose: fail-closed identity posture holds for every input class, not just well-formed JSON.
Output: hardened writer/loader + 2 regression scenes.
</objective>
