<objective>
Split ValidatorRegistry's CID loader into a raw core and an authorization-verifying public loader so a registry loaded by CID is verified against the genesis-rooted update chain before any certificate path consumes it (TRUST-01, finding #1; first half of the fix — Consensus-side consumption lands in plan 21-04).

Purpose: Today `LoadRegistryByCid` (ValidatorRegistry.cpp:785-820) reads `db_->GetLocalDeltaKeyValues(cid)` directly, bypassing the registry CRDT filter — a peer supplying a forged/self-certified RegistryUpdate CID gets it loaded unverified. The verification machinery (`VerifyUpdateClassified`, same file :1551-1836) already exists and is fail-closed at the broadcast path; this plan routes the CID-load path through it.

Output: Verified + unverified loaders in ValidatorRegistry, strict internal CID loads, deprecated alias kept green for callers plans 21-04 migrates, unit adversarial+compat test pairs.
</objective>
