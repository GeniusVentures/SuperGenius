```cpp
using ValidatorPtr = const IInputValidator *;
static void Register( const std::string &chain_id, ValidatorPtr validator ) { registry()[chain_id] = validator; }
static void UnregisterIf( const std::string &chain_id, ValidatorPtr expected )
{
    auto it = registry().find( chain_id );
    if ( it != registry().end() && it->second == expected ) { registry().erase( it ); }
}
static ValidatorPtr Get( const std::string &chain_id )
{
    auto it = registry().find( chain_id );
    return it != registry().end() ? it->second : nullptr;
}
private:
static std::unordered_map<std::string, ValidatorPtr> &registry()
{
    static std::unordered_map<std::string, ValidatorPtr> map;
    return map;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ISignedCRDTData implementer -> SecureCrdtRegistry | A future phase's data-type module registers itself; the registry must not let a malformed/hostile registration silently override another type's entry. |
| Test/caller -> SignerSetSource callback | The signer-set source is injected code (a lambda in this phase's tests, TrustedPeerRegistry in Phase 10) — SecureCrdtRegistry must treat its result as untrusted-until-verified at the Plan 02 wrapper layer, not assume the snapshot itself is authoritative without EvaluateQuorum. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `ISignedCRDTData::DeserializeFromBytes` | mitigate | Codec returns `false` on malformed/truncated bytes rather than throwing or asserting (V5 Input Validation) — mirrors `ValidatorRegistry::DeserializeRegistryUpdate`'s parse-failure-returns-error pattern; enforced by this plan's interface test asserting `DeserializeFromBytes({})` returns false. |
| T-09-02 | Elevation of Privilege | `SecureCrdtRegistry::UnregisterIf` | mitigate | Compare-and-remove idiom (copied from `IInputValidator::UnregisterIf`) requires the caller's token to match the registering token — a second, unrelated module cannot silently deregister another type's policy entry. |
| T-09-03 | Spoofing | `SignerSetSource` injectable callback | accept (this phase) | Phase 9 only ever injects test fixed-list lambdas; the real trust boundary (verifying the signer set itself came from a legitimate `TrustedPeerRegistry` quorum-updated set) is Phase 10's responsibility — out of this phase's scope per CONTEXT.md's phase boundary. Documented here so Phase 10 planning re-examines this boundary. |
| T-09-04 | Denial of Service | Regex compiled per registry entry (`std::regex` on `Register()`) | accept | Registration happens a small, bounded number of times at startup (one per registered data type, not per-request), so the cost of `std::regex` construction is negligible and not attacker-controlled input. |

</threat_model>
