<objective>
Migrate `ValidatorRegistry`'s genesis-path signature verification (`VerifyUpdate`, `ValidatorRegistry.cpp:1387-1406`) from a direct `GeniusAccount::VerifySignature` call onto the shared `multisig::VerifyPayloadSignature` primitive shipped in Phase 8. This is a narrow, like-for-like call-site substitution — no adapter, no new CRDT wiring, no quorum/storage changes. Wire the new `multisig` build dependency into `blockchain_genesis`.

Purpose: Prove the Phase 8 `multisig` primitive generalizes to a second consumer without forcing `ValidatorRegistry` into the (structurally incompatible, weighted-quorum) `ISignedCRDTData`/`SecureCrdt` framework. Per 12-CONTEXT.md D-01/D-02/D-03, this phase deliberately narrows the original MIG-05 wording (full `ISignedCRDTData` migration) to signature-verification-only reuse — REQUIREMENTS.md's MIG-05 text is superseded by 12-CONTEXT.md on this point.
Output: Updated `ValidatorRegistry.cpp` genesis-path verify call, updated `blockchain_genesis` CMake link list, and a verification run confirming no behavioral or stability regression (including the D-05 multi_account_test exit gate).
</objective>
