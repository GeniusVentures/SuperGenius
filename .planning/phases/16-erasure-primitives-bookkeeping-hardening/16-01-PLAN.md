<objective>
Build the CRDT-entry half of the atomic two-level erase: a `CrdtSet` batch-staging primitive that stages deletes for all four CRDT key families into a caller-owned `BufferBatch` (never committing, never firing hooks), plus the two small `CrdtDatastore` exposures GlobalDB's compose (16-03) needs — the now-public `IsRootCIDPendingOrActive` guard and a forwarding `StageEraseElement`.

Purpose: PRUNE-02 requires the CRDT set entries (`/crdt/s|t/<key>/<cid>`, `/crdt/k/<key>/v|p`) to disappear inside the same single RocksDB WriteBatch as the raw block and the tx→CID map entry. Key-layout knowledge stays inside `CrdtSet` (D-01); firing `deleteHookFunc_` is forbidden because it drives `TransactionManager::ProcessDeletion` → `RevertTransaction`, reverting genuine spends (RESEARCH Pitfall 1).

Output: Modified `crdt_set`/`crdt_datastore` sources with a new unit test suite in `crdt_set_test.cpp`. Zero production behavior change — the new methods have no production callers in this plan.
</objective>
