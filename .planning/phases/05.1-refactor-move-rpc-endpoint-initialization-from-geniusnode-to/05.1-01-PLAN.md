<objective>
Establish the new contracts for Phase 05.1: define the `IBridgeInitObserver` interface and re-signature `ChainRpcEndpointProvider::Initialize()` to take a `std::filesystem::path` to `bridge_chains_config.json`, performing all JSON reading, `chain_id` extraction, `IInputValidator::Register`, and observer notification internally. This is the interface-first plan that Plans 02 and 03 implement against.

Purpose: Move endpoint initialization OUT of GeniusNode (D-01, D-02). The provider becomes the single owner of config parsing + validator registration + chain-data handoff. By defining the observer contract here, downstream plans (BridgeRelayer as observer, GeniusNode as thin orchestrator) can be written against stable signatures.

Output: A new shared `ChainContractPair.hpp` header (breaks the include cycle between provider and relayer), updated `ChainRpcEndpointProvider.{hpp,cpp}` with the new `Initialize()` signature, `IBridgeInitObserver` interface, observer registration, `BridgeRelayer.hpp` updated to source the struct from the shared header, and an updated unit test file proving the new behavior (config-file-driven initialization, Register called, observers notified).
</objective>
