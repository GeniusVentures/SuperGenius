# Phase 04.2: P2P RLPx Burn Event Gossip - Context

**Gathered:** 2026-07-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Promote P2P RLPx burn event gossip from "Deferred — v1" (ROADMAP Out of Scope) to active.
Where Phases 4 and 04.1 trigger mints by *manually* calling `GeniusNode::MintTokens()` after a
`cast send`, Phase 04.2 lets the bridge events arrive **over the devp2p RLPx protocol** and flow
*autonomously* through the existing `BridgeRelayer::OnWatchEvent → TransactionManager::MintFunds`
pipeline — no manual mint trigger.

Three SuperGenius nodes each construct a real `EthWatchService` in RLPx production mode
(`initialize(config, callback)` + `run(io)`), discover Sepolia peers via discv4/discv5, complete
the ETH Status handshake, and receive `NewBlock` / `Receipts` eth-wire messages. The watcher
decodes `BridgeSourceBurned` / `BridgeOutInitiated` logs from the gossiped receipts and hands them
to the registered `BridgeRelayer` callback. Each decoded burn produces one minted UTXO.

The test streams burns to live Sepolia at 1-2 second intervals for 10-20 seconds (10-15 burns
total) and asserts that *every* burn tx hash surfaces as a distinct minted UTXO on all three
nodes. Requires a real Sepolia `PRIVATE_KEY` (account must hold GNUS).

</domain>

<decisions>
## Implementation Decisions

### Test Transport — RLPx, not WebSocket/HTTP
- **D-01:** The new test constructs `eth::EthWatchService` in **production RLPx mode** by calling
  `initialize(EthWatchServiceConfig, callback)` + `run(io_context)`. This is the same code path as
  `evmrelay/test/eth/eth_watch_all_chains_live_test.cpp`. The bare `EthWatchService()` constructed
  by `GeniusNode` (Phase 5, `GeniusNode.cpp:583`) only exposes `watch_event()` registration — it
  does NOT start RLPx sessions and is explicitly out of scope for 04.2 (no production node change).
- **D-02:** Discovery mode = `EthWatchDiscoveryMode::kDiscoverFirst` (matches the live test). The
  test does NOT dial cached `nodes` — it discovers real Sepolia peers. `discovery.bind_port = 0`
  and `discv5_discovery.bind_port = 0` (OS-assigned, avoids cross-test collisions).
- **D-03:** At least one burn must complete the full RLPx-detected → BridgeRelayer → MintFunds →
  UTXO round-trip. If RLPx connection cannot be established within the discovery window (env-tunable,
  default per D-09), the test `GTEST_SKIP`s with a clear message rather than failing.

### EthWatchServiceConfig construction
- **D-04:** Chain peer config loaded via `evmrelay::examples::load_chain_peer_config(
  "ethereum-sepolia", argv0, chain_peers_json_path, ...)`. The chain name is fixed to
  `"ethereum-sepolia"`. The `chain_peers_json_path` comes from `EVMRELAY_LIVE_SEPOLIA_JSON` env
  override; if unset, the helper falls back to the `chain_enodes.json` next to the test binary
  (matches the live all-chains test pattern).
- **D-05:** Bridge watch spec registered on the *test-owned* `EthWatchService` using the same
  `event_signature` / `params` that `BridgeRelayer::Start()` uses:
  `BridgeSourceBurned(address,uint256,uint256,uint256,uint256,bytes)` (v1) and
  `BridgeOutInitiated(address,uint256,uint256,uint256,uint256,bytes32,bool)` (v2), sourced from
  `eth::cli::event_registry().params_for(...)`. This keeps the test's ABI decoding identical to
  production.
- **D-06:** `EthWatchConnectionConfig`: `max_connections_per_chain = 3` (matches the default and
  the live test), `max_total_connections = 9` (3 chains × 3 — conservative for a test). The live
  all-chains test uses 24/3; 04.2 only watches one chain so 9 is ample.

### BridgeRelayer reuse — no production wiring change
- **D-07:** The test instantiates its own `sgns::BridgeRelayer` pointed at the test-owned
  `EthWatchService`, NOT at `GeniusNode::eth_watch_service_`. The test's `BridgeRelayer` receives
  the three nodes' `TransactionManager` weak refs and fires `MintFunds` directly. This proves the
  RLPx → BridgeRelayer → MintFunds path end-to-end without modifying `GeniusNode` (production
  RLPx enablement is a follow-up, out of scope per ROADMAP "Deferred → now active" note which is
  test-scoped).
- **D-08:** `BridgeRelayer::Start()` is called with a single
  `ChainContractPair{ "ethereum-sepolia", kSepoliaBridgeContractLower }`. The relayer's dual
  v1+v2 watch registration (Phase 05.2) is reused unchanged.

### Test timing & burn cadence
- **D-09:** Discovery + handshake settle window: **30 seconds** (env-tunable via
  `SGNS_RLPX_SETTLE_SECONDS`, default 30). The test polls
  `service.aggregate_connection_stats().remote_status_accepted >= 1` via `wait_condition` before
  sending the first burn. If the threshold is not met, `GTEST_SKIP` (D-03).
- **D-10:** Burn cadence: **one `cast send` every 1-2 seconds** (jittered via
  `std::chrono::milliseconds{ 1000 + (i * 137) % 1000 }` — deterministic pseudo-jitter, no RNG).
  Total burns: **10** (env-tunable via `SGNS_RLPX_BURN_COUNT`, default 10). Total streaming
  duration ≈ 10-20 seconds as specified.
- **D-11:** Mint appearance timeout per burn: **45 seconds** from the burn's `cast send` return.
  RLPx gossip + Sepolia block inclusion + BridgeRelayer decode + MintFunds consensus round can
  each take seconds; 45s is generous. Polled via `EXPECT_WAIT_FOR_CONDITION`.

### Verification — every burn mints
- **D-12:** For each burn tx hash, the test asserts that `node_main`, `node_proc1`, and
  `node_proc2` each show a balance increase of `>= kMintAmount` at the burn's destination address.
  The destination address is the node's own SuperGenius address (same as Phase 4 / 04.1 pattern).
  Because all three nodes watch the same Sepolia contract via RLPx, all three should mint
  independently — verifying true P2P event gossip (not node-to-node mint propagation).
- **D-13:** The test records each `(burn_tx_hash, initial_balance, final_balance)` tuple via
  `spdlog::info` for post-run diagnosis. No `fprintf`/`cout`/`printf` (CLAUDE.md rule).

### Environment gating
- **D-14:** Test guarded by **both** `RUN_E2E_RLPX=1` **and** `PRIVATE_KEY` (or `SIGNING_KEY`).
  Skips cleanly (GTEST_SKIP) when either is absent — same gating discipline as Phase 4 / 04.1.
  RLPx test is opt-in because it consumes real Sepolia resources and requires a funded account.
- **D-15:** `cast` and `anvil` availability checked via the existing `CastAvailable()` helper
  from `anvil_fixture.hpp`. `anvil` is NOT required for 04.2 (we hit live Sepolia, not a local
  fork), but `cast` is mandatory for `cast send`. The test reuses `CastAvailable()` and adds no
  new binary check beyond it.

### Code placement
- **D-16:** New test file: `test/src/bridge_e2e/bridge_rlpx_e2e_test.cpp`. New test target
  `bridge_rlpx_e2e_test` appended to `test/src/bridge_e2e/CMakeLists.txt`, mirroring the
  `bridge_anvil_e2e_test` block (links `genius_node_test` + `json_secure_storage`, includes
  `${AsyncIOManager_INCLUDE_DIR}`, three-platform whole-archive link options). Reuses
  `OpenCommandPipe`/`CloseCommandPipe`/`ParseTxHashFromCastJson`/`NormalizePrivateKey` helpers
  from the existing `bridge_e2e_test.cpp` / `anvil_fixture.hpp` (no duplication — include the
  helpers).
- **D-17:** No new headers required. The test includes:
  `<eth/eth_watch_service.hpp>`, `<eth/eth_watch_runner.hpp>` (transitively),
  `evmrelay/examples/chain_config.hpp`, `"account/BridgeRelayer.hpp"`, `"account/GeniusNode.hpp"`,
  `"testutil/wait_condition.hpp"`, `"testutil/outcome.hpp"`.

### Claude's Discretion
- Exact discovery settle timeout (D-09 default proposed)
- Exact burn count and cadence formula (D-10 proposed)
- Whether to assert all-3-nodes-mint (D-12) or main-node-only with quorum-implies-propagation
  (Phase 4 chose the latter; 04.2 prefers all-3 because RLPx gossip is the point)
- Fixture class name (`BridgeRlpxE2ETest` proposed)
- How to surface per-burn diagnostics (D-13 — spdlog chosen)

</decisions>

## Existing Code Insights

### Reusable Assets
- **`eth_watch_all_chains_live_test.cpp`** — The RLPx production-mode template. 04.2 copies its
  `EthWatchServiceConfig` construction (kDiscoverFirst, bind_port=0) and its
  `aggregate_connection_stats().remote_status_accepted` polling pattern. The only divergence: 04.2
  registers a `BridgeRelayer` callback (the live test registers a no-op lambda).
- **`BridgeE2ETest` fixture** — 3-node setup, PubSub bootstrap, Sepolia RPC endpoint config. 04.2
  reuses this verbatim for the SuperGenius node side and layers RLPx watching on top.
- **`BridgeRelayer`** — Unchanged. `Create(tx_manager, watch_service)` + `Start({chains})`
  registers dual v1+v2 watches. The test points this at its own RLPx-running EthWatchService.
- **`anvil_fixture.hpp` helpers** — `CastAvailable()`, `ParseTxHashFromCastJson()`,
  `kSepoliaBridgeContractLower`, `kBridgeEventTopic0`. Include, don't duplicate.

### Established Patterns
- GTest fixture with `SetUpTestSuite`/`TearDownTestSuite` (process-scoped node + RLPx service
  lifecycle).
- `GTEST_SKIP()` for env-gated tests (`RUN_E2E_RLPX`, `PRIVATE_KEY`).
- `popen()`/`pclose()` shell-out for `cast send` (Phase 4 / 04.1).
- `wait_condition` polling for node READY, RLPx handshake, balance increase (no `sleep_for`).
- `DevConfig` per node with separate `BaseWritePath` (`./nodeN/`).
- RLPx service intentionally leaked across GTest teardown (the live test notes this:
  "Stopping active Boost coroutine sessions during GTest teardown can surface forced_unwind").
  04.2 follows the same pattern — the test-owned `EthWatchService` is heap-allocated and left for
  process exit, matching `eth_watch_all_chains_live_test.cpp:232`.

### Integration Points
- **RLPx service ↔ BridgeRelayer:** test-owned `EthWatchService` constructed → `initialize(config,
  BridgeRelayerCallback)` → `run(io)`. The `BridgeRelayer` is constructed with the same service
  and calls `Start({ChainContractPair})` to register watches BEFORE `run()` (so sessions pick up
  subscriptions on connect).
- **BridgeRelayer ↔ TransactionManager:** `BridgeRelayer::Create(weak_tx_manager, watch_service)`.
  The test passes each node's `transaction_manager_` weak ref. Three nodes → three separate
  `BridgeRelayer` instances sharing one `EthWatchService`? **No** — each node gets its own
  `EthWatchService` (the test needs to prove each node independently receives RLPx events).
  See D-07 clarification: one service per node.
- **`cast send` → live Sepolia:** unchanged from Phase 4; target `kSepoliaRpc` (public RPC), not
  a local Anvil port. The burn lands on-chain, gets gossiped via devp2p, reaches the three
  nodes' RLPx sessions.

<specifics>
## Specific Ideas

- The test binary's `argv[0]` is used by `load_chain_peer_config` to locate `chain_enodes.json`
  next to the executable (same as the live test's `kChainConfigArgv0Env` fallback). The test
  reads `boost::dll::program_location().string()` for this (already used in `bridge_e2e_test.cpp`
  line 287 for `BaseWritePath`).
- Each node constructs its own `boost::asio::io_context` for its RLPx service OR all three share
  the node's existing `io_`. **Decision: each test-owned RLPx service gets its own
  `io_context`** run on a dedicated `std::thread` (3 threads total), to avoid contending with the
  nodes' internal io_context. Threads joined in `TearDownTestSuite` before the services are
  abandoned. (The services themselves are leaked per the live-test pattern; only the io_context
  threads are joined.)
- The GNUS-funding problem: the `PRIVATE_KEY` account must already hold GNUS on live Sepolia
  (10-15 burns × 1 unit each). If it doesn't, the first `cast send` reverts and the test fails
  at the burn step — clear error, no silent skip. The test does NOT attempt
  `anvil_impersonateAccount` against live Sepolia (impossible — that's an Anvil-only RPC).
- The test does NOT call `GeniusNode::MintTokens()` anywhere. The entire point is that RLPx
  events drive `BridgeRelayer::OnWatchEvent → MintFunds` autonomously. Manual `MintTokens` would
  defeat the purpose.
- Not CI-runnable (requires `cast`, live Sepolia access, funded PRIVATE_KEY, and real RLPx peers).

</specifics>

## Deferred Ideas

- **Production GeniusNode RLPx enablement** — wiring `EthWatchService::initialize()/run()` into
  `GeniusNode::InitializeAndStartBridge()` (replacing the bare `EthWatchService()` at
  `GeniusNode.cpp:583`). This is a production node change; 04.2 is test-only. Deferred to a
  follow-up phase.
- **Cache-first discovery mode** (`kCacheOnly`, `kHybrid`) — 04.2 uses kDiscoverFirst exclusively
  to prove real peer discovery. Other modes are operational concerns for production.
- **Mock-peer RLPx test** — `eth_watch_mock_peer_test.cpp` already covers the injected-dialer
  seam. 04.2 does not add a new mock-peer test; it proves the live path.
- **Cross-chain gossip** (Polygon, Base, etc.) — 04.2 watches Sepolia only. Multi-chain is a
  production concern.

</deferred>
