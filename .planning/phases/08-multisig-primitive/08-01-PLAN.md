<objective>
Create the standalone MultiSig primitive: a header/cpp component in `src/multisig/` that (1) verifies a signature over an arbitrary raw-byte payload by delegating to `GeniusAccount::VerifySignature`, and (2) evaluates N-of-M quorum over a signer set + collected signatures with dedup-by-signer and skip-invalid-silently semantics (D-03, D-04). No CRDT, no node, no network dependency (MSIG-03).

Purpose: This is the foundational primitive Phase 9 (SecureCRDT) builds on. It must be independently compilable/testable and reusable without modification by later phases.

New public API to create in src/multisig/MultiSig.hpp (namespace `sgns::multisig`, per PATTERNS.md preference to mirror `sgns::crypto`):
```
bool VerifyPayloadSignature( const std::string &address,
                              std::string_view   signature,
                              const std::vector<uint8_t> &payload );

struct QuorumResult
{
    bool     has_quorum         = false;
    uint64_t valid_unique_count = 0;
};

QuorumResult EvaluateQuorum( const std::vector<std::string>                         &signer_set,
                             uint64_t                                                threshold,
                             const std::vector<std::pair<std::string, std::string>> &collected_signatures,
                             const std::vector<uint8_t>                             &payload );
```
`EvaluateQuorum` ordering rule (D-04, RESEARCH.md Pitfall 3): for each (address, signature) in `collected_signatures`, skip if `address` already in `valid_unique_signers` (dedup-first), skip if `address` not in `signer_lookup` (unauthorized), skip if `VerifyPayloadSignature` fails (invalid signature) — only then insert into `valid_unique_signers`. `has_quorum = valid_unique_signers.size() >= threshold`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → MultiSig::VerifyPayloadSignature | Caller-supplied (address, signature, payload) may be attacker-controlled (e.g. a malicious CRDT replica peer in Phase 9's future usage) |
| Caller → MultiSig::EvaluateQuorum | Caller-supplied `collected_signatures` may contain duplicate, forged, or unauthorized-signer entries mixed with legitimate ones |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Spoofing | `VerifyPayloadSignature` | mitigate | Delegates entirely to `GeniusAccount::VerifySignature`, which performs the project's proven secp256k1/double-SHA256 verification (`GeniusAccount.cpp:824-838`); no custom crypto is written, eliminating a class of forgery bugs from a from-scratch implementation |
| T-08-02 | Tampering | `VerifyPayloadSignature` (payload/signature bytes) | mitigate | Task 1 behavior tests explicitly assert tampered payload and tampered signature both verify false; `GeniusAccount::VerifySignature`'s `SIGNATURE_EXP_SIZE == 64` check rejects malformed-size signatures before any EC math runs |
| T-08-03 | Elevation of Privilege / Quorum bypass via duplicate-signer counting | `EvaluateQuorum` | mitigate | D-04's dedup-by-signer-before-verify ordering (enforced by Task 2 acceptance criteria: dedup check textually precedes `VerifyPayloadSignature` call) guarantees one signer contributes at most one unit toward `valid_unique_count`, regardless of how many entries for that signer appear in `collected_signatures` |
| T-08-04 | Elevation of Privilege / Unauthorized signer inclusion | `EvaluateQuorum` | mitigate | `signer_lookup` membership check rejects any (address, signature) pair whose address is not in the authorized `signer_set`, even if the signature itself is cryptographically valid against some other payload/keypair — Task 2 behavior test covers this explicitly |
| T-08-05 | Repudiation / Replay of old signatures across different payloads or quorum epochs | `EvaluateQuorum` (cross-invocation, stateless by design D-03) | accept — scope boundary | Per D-03, `EvaluateQuorum` is intentionally stateless and re-invoked by the caller each time with the *current* signature set; anti-replay (e.g. rejecting a signature over a stale/superseded payload, or one already consumed in a prior quorum round) is explicitly the CRDT-backed caller's responsibility per D-03/D-04 rationale, deferred to Phase 9 (SecureCRDT layer) where CRDT key/value versioning provides the natural replay boundary. Called out explicitly here rather than silently ignored, per this phase's stated non-goal (CONTEXT.md domain: "does NOT touch CRDT") |
| T-08-06 | Denial of Service via malformed/oversized signature or payload input | `VerifyPayloadSignature`, `EvaluateQuorum` | mitigate | Inputs are `std::string_view`/`std::vector<uint8_t>` bounded by caller memory; `GeniusAccount::VerifySignature`'s existing size check fails fast on non-64-byte signatures without attempting EC parsing; no unbounded loops (`EvaluateQuorum`'s loop is bounded by `collected_signatures.size()`, a caller-controlled but not attacker-amplifiable input at this layer) |
</threat_model>
