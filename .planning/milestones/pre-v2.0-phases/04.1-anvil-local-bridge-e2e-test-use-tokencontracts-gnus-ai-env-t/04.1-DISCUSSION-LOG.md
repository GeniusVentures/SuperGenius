## evmrelay vs. Direct RPC

| Capability | Anvil Support | Implications |
|------------|---------------|--------------|
| JSON-RPC (eth_*, anvil_*) | Yes | Deployment and testing ✓ |
| WebSocket subscriptions | Likely yes | eth_subscribe for logs/newHeads |
| RLPx/devp2p | No | No p2p discovery — point directly at ws:// |
| ETH wire protocol | No | No block/tx gossip |

**User's choice:** Point evmrelay directly at Anvil's WebSocket endpoint. If subscriptions don't work, fall back to Sepolia direct test.

**Notes:** evmrelay cannot discover Anvil via p2p — must be configured with explicit WebSocket URL. This mirrors the mock transport pattern from Phase 5 (explicit endpoint configuration).

## Key Sourcing (.env vs. Anvil Defaults)

| Option | Description | Selected |
|--------|-------------|----------|
| Copy .env from TokenContracts | Developer copies once, .gitignored | |
| Source .env directly | Read from ../TokenContracts/ path | |
| Anvil default keys | Use Anvil's deterministic pre-funded accounts, fund with GNUS via impersonation | ✓ |

**User's choice:** Use Anvil's default keys (account #0). No .env file needed. Fund the account with GNUS tokens via `anvil_impersonateAccount` on a Sepolia GNUS holder.

**Notes:** This is cleaner — zero external dependencies. Anvil's 10 default accounts each have 10,000 ETH. The test just needs to get GNUS tokens to one of them on the forked Sepolia. Impersonation approach: impersonate a known Sepolia GNUS holder, transfer GNUS to the Anvil default account via ERC-20 `transfer`, stop impersonating.
