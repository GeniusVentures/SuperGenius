**Commit:** `a716c13c`

`sgns::test::anvil::SendBridgeOutBurn` helper (which calls the real
`bridgeOut(uint256,uint256,uint256,bytes32,bool)` path and emits the

### WR-01: `EXPECT_WAIT_FOR_CONDITION` macro internally raises a FATAL failure — name lies about non-fatality

**Files modified:** `test/testutil/wait_condition.hpp`
**Commit:** `ba530fea`
**Applied fix:** In `expectWaitForCondition`, changed the `TestPartResult`
kind from `kFatalFailure` to `kNonFatalFailure`. `assertWaitForCondition`
(line 97) remains `kFatalFailure` so the two helpers now differ in fatality
to match their names and gtest's `EXPECT_*`/`ASSERT_*` convention. Updated

**Shared-header safety rationale:** The non-fatal behavior is the helper's
documented contract (Doxygen at line 109 says "non-fatal assertion"). Any
test that appeared to rely on the fatal-abort was doing so against a bug;
those tests will now correctly continue to their later diagnostic
assertions, which is the intended `EXPECT_` semantics. The fix is adopted by
the reviewer's recommendation and is the least-invasive correct change.

### WR-02(c): Subprocess leak risk — `Stop()` blocks forever if child ignores SIGTERM

**Files modified:** `test/src/bridge_e2e/anvil_fixture.hpp`
**Commit:** `93fae303`
**Applied fix:** Added SIGKILL escalation to `AnvilProcess::Stop()`.
`SIGTERM` → poll `waitpid(WNOHANG)` for a bounded grace period
(`kStopGracePeriodMs = 5000ms`, polled every `kStopPollIntervalMs = 50ms`
via `waitForCondition`, no `sleep_for` in test code) → if not reaped,
escalate to `SIGKILL` + final blocking `waitpid`. A misbehaving Anvil child
can no longer hang test-suite teardown via the `AnvilProcess` destructor.
Added `kStopGracePeriodMs` and `kStopPollIntervalMs` constexpr constants.
**Status:** fixed: requires human verification (logic fix — teardown timing
on a misbehaving Anvil child).

### WR-02(a)+(b): AnvilProcess POSIX-only fork/SIGTERM/dev-null — now cross-platform via boost::process

**Files modified:** `test/src/bridge_e2e/anvil_fixture.hpp`,
`test/src/bridge_e2e/bridge_anvil_e2e_test.cpp`
**Applied fix:** Rewrote `AnvilProcess` to use the thirdparty
`boost::process` (Boost 1.85) instead of raw POSIX. `Start()` spawns via
`bp::search_path("anvil")` + `bp::child(...)` with `bp::std_in/std_out/std_err
> bp::null` — fork/exec on POSIX, `CreateProcess` on Windows, zero `#ifdef`.
`Stop()` calls `terminate()` (SIGKILL on POSIX / `TerminateProcess` on Windows
— uncatchable, so the child is guaranteed to exit) then a blocking `wait()`
to reap, using the `std::error_code` overloads so the destructor cannot throw
and teardown cannot hang. Spawn failure / missing binary now throws
`system_error`, caught and reported via spdlog (replaces the old silent
`_exit(127)`). Dropped the four unconditional POSIX headers (`sys/types.h`,
`sys/wait.h`, `unistd.h`, `csignal`) that blocked Windows compilation, and
the now-dead `kStopGracePeriodMs` / `kStopPollIntervalMs` constants (the
deprecated `child::wait_for` is no longer used). Initial recompile also
surfaced a latent bug at `bridge_anvil_e2e_test.cpp:564`
(`sgns::waitForCondition` — wrong namespace; the fixture resolves the symbol
unqualified), fixed by dropping the bogus qualifier.
**Verification:** `bridge_anvil_e2e_test` 2/2 and
`bridge_anvil_catchup_e2e_test` 3/3 pass; teardown logs
`anvil_fixture: stopped anvil exit_code=...` via the new path.
**Status:** fixed: requires human verification (Windows spawn/stop runtime —
only POSIX verified here).
