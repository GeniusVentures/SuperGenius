Why standalone watchers for Tests B and C (not the node-owned watcher):
The production BridgeCatchupWatcher is constructed by GeniusNode::InitializeAndStartBridge with the
default Config (start_block=0). The node does NOT expose a public setter for start_block, and adding
one would expand the change beyond the minimal D-22 injection. D-22 explicitly says "Tests B and C
inject this via Config::start_block" — so the test constructs BridgeCatchupWatcher directly with the
injected start_block value. Because poll_once() is private (called by the internal watch() loop),
the test needs friend access to drive a deterministic single poll. The friend declaration is the
narrowest possible accessor (1 line, no API surface change, no production code path affected).
