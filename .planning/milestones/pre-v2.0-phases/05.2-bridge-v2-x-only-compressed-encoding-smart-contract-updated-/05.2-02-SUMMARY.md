# Phase 05.2 Plan 02: BridgeRelayer Dual v1/v2 Event Watch + Variant Dispatch Summary

Updated `BridgeRelayer` to register BOTH `BridgeSourceBurned` (v1) and `BridgeOutInitiated` (v2) watches per chain in `Start()`, and to dispatch v1/v2 events in `OnWatchEvent()` on the variant type of `values[5]` (`ByteBuffer` → hex destination vs `Hash256` → `DecompressXOnlyPubkey` with the Y-parity bool from `values[6]`), keeping the v1 path byte-for-byte unchanged.

- **Completed:** 2026-06-19T00:36:42Z

- **Files modified:** 2

## Accomplishments

- `Start()` now registers two watches per chain (v1 `BridgeSourceBurned` 6-param + v2 `BridgeOutInitiated` 7-param with `bool destinationYOdd`), each in its own try/catch (D-21 best-effort), with the watch IDs stored as a `pair<v1_id, v2_id>` keyed by chain name.
- `OnWatchEvent()` dispatches on `std::holds_alternative` of `values[5]`: v1 `ByteBuffer` path is unchanged (64-byte destination → `hex_bytes`), v2 `Hash256` path extracts the 32-byte X-only key plus the Y-parity bool from `values[6]` and calls `eth::DecompressXOnlyPubkey` to build the 128-char destination.
- No `MintFunds` signature or behavior change — both paths converge on the existing downstream flow (dedup, logging, mint submission).

## Decisions Made

- **Map value type:** Used `std::pair<EventWatchId, EventWatchId>` rather than a new struct — minimal change, no new type to declare, consistent with the plan's recommended approach.
- **Shared callback:** Both v1 and v2 watches share a single `DecodedEventCallback` lambda that forwards to `OnWatchEvent()`; the dispatch happens inside `OnWatchEvent()` via the variant discriminator, so one callback serves both event versions.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Adapted to Plan 01's actual v2 event signature (7 params, not 6) and 2-arg DecompressXOnlyPubkey**
- **Found during:** Task 1 / Task 2 (pre-implementation interface verification against Plan 01's delivered code in `evmrelay/include/eth/eth_watch_cli.hpp` and `secp256k1_utility.hpp`)
- **Issue:** This plan's `<interfaces>` block sketched v2 as `BridgeOutInitiated(address,uint256,uint256,uint256,uint256,bytes32)` (6 params) and `DecompressXOnlyPubkey(contract_x_bytes)` (1 arg). Plan 01 actually delivered a 7-param event — `BridgeOutInitiated(...,bytes32 sgnsDestination, bool destinationYOdd)` — and a 2-arg decompression function `DecompressXOnlyPubkey(contract_x_bytes, destination_y_odd)`. Plan 01 introduced the explicit `destinationYOdd` bool so decompression is deterministic (single prefix, no parity trial — see 05.2-01 SUMMARY decision D-09). Implementing the sketched 6-param/1-arg contract would have failed to compile against Plan 01's headers and would have thrown away the deterministic-parity property.
- **Fix:** Registered the v2 watch with the real 7-param signature and the EventRegistry's params; in `OnWatchEvent()`, extracted `values[6]` as the `bool` Y-parity and passed it to the 2-arg `DecompressXOnlyPubkey`. Added a bounds check (`values.size() <= 6`) and a `holds_alternative<bool>` check before reading the parity param, hardening against malformed v2 events (T-05.2-04 mitigation).
- **Files modified:** `src/account/BridgeRelayer.cpp`
- **Verification:** `clang++ -fsyntax-only` with the main build's full flag set (includes Plan 01's `secp256k1_utility.hpp` + `eth_watch_cli.hpp`) — exit 0, clean. All plan-level `<verification>` greps pass.
- **Committed in:** `1d7d4449` (Task 1, event-sig string) and `ad409d5f` (Task 2, decompression call)

**2. [Rule 2 - Missing Critical] Added bounds + variant-type checks before reading the v2 parity bool (values[6])**
- **Found during:** Task 2
- **Issue:** The plan's `<action>` described extracting `values[5]` and decompressing, but did not guard the `values[6]` parity access. A malformed/truncated v2 event with only 6 values would cause OOB access, and a non-bool `values[6]` would throw `std::bad_variant_access` — both directly contradict the threat model's T-05.2-04 (mitigate wrong-variant access).
- **Fix:** Before reading `values[6]`, assert `values.size() > kV2DestinationYOddIndex` (log + return on failure) and `std::holds_alternative<bool>(values[6])` before `std::get<bool>`.
- **Files modified:** `src/account/BridgeRelayer.cpp`
- **Verification:** syntax check exit 0; logic inspected in the dispatch block.
- **Committed in:** `ad409d5f` (Task 2)
