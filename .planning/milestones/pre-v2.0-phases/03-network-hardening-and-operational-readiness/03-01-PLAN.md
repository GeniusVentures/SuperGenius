<objective>
## Phase Goal

**As a** consensus validator operator, **I want to** run a production-ready node that enforces message size limits before publishing, tolerates global clock skew, and exposes operational metrics for monitoring, **so that** the voting protocol is robust at scale across geographically distributed validators.

### This Plan (03-01)

Delivers three independently valuable hardening features that share TransactionManager as their implementation host:

1. **SIZE-01:** Pre-publish 64KB size gate at `SendTransactionItem` — oversized transactions are rejected immediately with `outcome::failure` instead of being silently dropped by PubSub.
2. **TS-01:** Configurable timestamp tolerance — the ±5min default is externally configurable through the existing `SetTimeFrameToleranceMs` → `DevConfig` path.
3. **METRICS-01:** Operational observability — atomic counters track vote rates and validation breakdown; lifecycle events logged at info level; counters flushed on TransactionManager destruction.

Purpose: Harden the network boundary (size), enable distributed validator participation (time), and provide production debuggability (metrics).
Output: TransactionManager.cpp with size gate + counter increments + lifecycle logs + destructor flush; TransactionManager.hpp with counter declarations; GeniusNode with TS-01 config wiring; consensus_subject_test.cpp with tests for all three.
</objective>
