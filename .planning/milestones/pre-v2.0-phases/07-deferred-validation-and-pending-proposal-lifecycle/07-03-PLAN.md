<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer proposal -> ConsensusManager | Untrusted remote proposal data enters local validation and pending storage. |
| dependency event -> pending retry | Local CRDT/certificate arrivals wake pending proposals and can trigger repeated validation. |
| ConsensusManager -> TransactionManager cleanup | Local expiry/certification callbacks change transaction tracking state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | pending proposal pool | mitigate | Enforce D-08 through D-10: global proposal count, per-proposer count, and retained-byte limits before admission. |
| T-07-02 | Denial of Service | retry scheduler and dependency wakeups | mitigate | Store retry metadata centrally so Plan 04 can throttle due retries without duplicated timers. |
| T-07-03 | Tampering / Elevation of Privilege | local Approval vote retry path | mitigate | Keep pending entries separate from `SlotState::voted`; retries still route through the Plan 02 approval path. |
| T-07-04 | Tampering | dependency key indexing | mitigate | Index by `PendingDependencyKey` typed hash/equality, not raw strings, preventing Certificate/hash collision with future key classes. |
| T-07-05 | Repudiation / Integrity | transaction state on inconclusive expiry | mitigate | Cleanup helper removes local consensus pending state only; transaction-state classification remains in Plan 05. |
</threat_model>
