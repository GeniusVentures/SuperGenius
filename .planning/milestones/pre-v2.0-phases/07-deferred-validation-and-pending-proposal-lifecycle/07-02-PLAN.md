<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer proposal -> ConsensusManager | Untrusted remote proposal data enters local validation and pending storage. |
| dependency event -> pending retry | Local CRDT/certificate arrivals wake pending proposals and can trigger repeated validation. |
| ConsensusManager -> TransactionManager cleanup | Local expiry/certification callbacks change transaction tracking state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | pending proposal pool | mitigate | This plan defines typed pending metadata only; Plan 03 enforces admission limits before state can grow unbounded. |
| T-07-02 | Denial of Service | retry scheduler and dependency wakeups | mitigate | This plan prevents direct vote writes on retry; Plan 04 adds throttle/backoff controls. |
| T-07-03 | Tampering / Elevation of Privilege | local Approval vote retry path | mitigate | Route all approvals through `ContinueProposalAfterSubject()` so `SlotState::voted` and `seen_voters` remain authoritative. |
| T-07-04 | Tampering | dependency key indexing | mitigate | Use `PendingDependencyKey::Type::Certificate` plus value instead of raw strings to avoid dependency-key collisions. |
| T-07-05 | Repudiation / Integrity | transaction state on inconclusive expiry | mitigate | Preserve Reject as local terminal validation only; Plan 05 adds UNCONFIRMED for inconclusive expiry. |
</threat_model>
