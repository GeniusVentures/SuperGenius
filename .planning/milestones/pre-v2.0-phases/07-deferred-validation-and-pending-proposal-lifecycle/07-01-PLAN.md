<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer proposal -> ConsensusManager | Untrusted remote proposal data enters local validation and pending storage. |
| dependency event -> pending retry | Local CRDT/certificate arrivals wake pending proposals and can trigger repeated validation. |
| ConsensusManager -> TransactionManager cleanup | Local expiry/certification callbacks change transaction tracking state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | pending proposal pool | mitigate | Tests must cover global count, per-proposer count, and retained-byte admission limits per D-08, D-09, D-10. |
| T-07-02 | Denial of Service | retry scheduler and dependency wakeups | mitigate | Tests must cover bounded backoff and minimum dependency-trigger retry interval per D-05 and D-06. |
| T-07-03 | Tampering / Elevation of Privilege | local Approval vote retry path | mitigate | Tests must assert retry emits at most one local Approval and does not double-count validator weight per D-07. |
| T-07-04 | Tampering | dependency key indexing | mitigate | Tests must use typed dependency keys and include Certificate(tx_hash) wakeups to prevent raw-string collision per D-03. |
| T-07-05 | Repudiation / Integrity | transaction state on inconclusive expiry | mitigate | Tests must distinguish UNCONFIRMED expiry from FAILED proven-invalid transactions per D-13 through D-15. |
</threat_model>
