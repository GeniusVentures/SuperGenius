## Scope of What Moves

| Option | Description | Selected |
|--------|-------------|----------|
| Partial move | Just JSON reading + provider construction; path resolution stays in GeniusNode | |
| Full move | `Initialize()` accepts `std::filesystem::path`; path resolution stays in GeniusNode, JSON parsing moves in | ✓ |

**User's choice:** `Initialize()` accepts `std::filesystem::path`. GeniusNode resolves the path (it owns BaseWritePath), then passes it to provider.Initialize(path, validator, logger).

---

## IInputValidator::Register() Placement

| Option | Description | Selected |
|--------|-------------|----------|
| Stay in GeniusNode | Register() remains in GeniusNode after provider.Initialize() returns | |
| Move into provider | Register() called inside ChainRpcEndpointProvider::Initialize() after wiring | ✓ |

**User's choice:** Nothing but `ChainRpcEndpointProvider::Initialize()` should remain in GeniusNode. `IInputValidator::Register()` moves into the provider as the final step.

---

## Coupling Pattern — BridgeRelayer ↔ ChainRpcEndpointProvider

| Option | Description | Selected |
|--------|-------------|----------|
| A. Provider getter | `GetBridgeChains()` const getter; GeniusNode reads and passes to BridgeRelayer | |
| B. Observer callback | `IBridgeInitObserver` interface; BridgeRelayer subscribes before Initialize(), provider notifies on completion | ✓ |
| C. DI into BridgeRelayer | `BridgeRelayer::Initialize(const ChainRpcEndpointProvider&)` queries directly | |

**User's choice:** Observer callback (B). Async-friendly — subscription happens synchronously before `boost::asio::post(Initialize())`, callbacks fire inside Initialize() on the io_context. BridgeRelayer implements `IBridgeInitObserver::OnRpcEndpointsReady(vector<ChainContractPair>)` and calls `Start()`.

**Notes:** GeniusNode owns both provider and BridgeRelayer — non-owning `IBridgeInitObserver*` in the observer list, no lifetime issues.

## Chain ID Source (kChainNameToId)

| Option | Description | Selected |
|--------|-------------|----------|
| Move map to provider | Hardcoded map moves alongside the code | |
| Eliminate the map | Chain IDs from `bridge_chains_config.json` (`chain_id` field) or chainlist.org data | ✓ |

**User's choice:** Eliminate `kChainNameToId`. Chain IDs are sourced from `bridge_chains_config.json` (new `chain_id` field per chain entry) or from chainlist.org/rpcs.json data. Chains without a `chain_id` are skipped with a warning.
