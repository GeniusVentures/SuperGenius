# Phase 4 Plan 02: Negative Test Cases

## Objective

Add three negative test cases validating Phase 3 security fixes: replay rejection via dedup cache, fail-closed on missing RPC endpoints, and invalid receipt log rejection via verify_receipt_log.

## must_haves

- ReplayRejection: call MintTokens twice with same burn tx hash, second call rejected by dedup cache
- MissingEndpointsFailClosed: call MintTokens for chain "999999" (no configured RPC endpoints), verify fail-closed
- InvalidReceiptLogsRejected: standalone TEST() verifying verify_receipt_log rejects wrong contract (kContractMismatch) and wrong topic0 (kTopic0Mismatch)
- All tests compile and register in bridge_e2e_test binary

## Tasks

### Task 1: ReplayRejection test

<objective>
Add TEST_F BridgeE2ETest ReplayRejection: call MintTokens twice with the same burn tx hash, verify the second call is rejected by the dedup cache, proving Phase 3 deduplication works.
</objective>

<read_first>
- test/src/bridge_e2e/bridge_e2e_test.cpp (fixture from 04-01)
- src/account/TransactionManager.cpp (MintFunds call path)
</read_first>

1. Generate unique burn tx hash via NextMintSourceHash()

<acceptance_criteria>
